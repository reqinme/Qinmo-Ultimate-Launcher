# ADR · 架构决策记录（登记册）

> **版本**：与方案 `v3.13` 对应 ｜ **建立时机**：M0 之前
>
> ## 为什么这里只有一个文件，而不是 8 个 ADR 文件
>
> 方案 §1.5 建立了 ADR 机制并列出首批 8 条。但实际盘点后发现：**这些决策的全部内容已经写在 `方案-重新立意版.md` 里了**
> （每条都有"背景 / 备选 / 决定 / 理由 / 后果"，且**已带源码或实测证据**）。
>
> 如果为它们再建 8 个独立文件，就会出现**同一决策有两个真源**——而"双真源会漂移"正是本方案反复强调要避免的
> （见 §5.5 对 `patches/` 双真源的批评、§6.3 对尖刺编号撞车的处理）。
>
> **因此本文件是"登记册 + 索引"**：只记录**决策编号、状态、一句话结论、以及方案中的位置**。
> **决策的详细论证以方案对应章节为唯一真源。**
>
> ### 什么时候才需要新建独立 ADR 文件
>
> **满足任一条即新建**（文件名 `ADR-00NN-<短标题>.md`）：
> 1. **推翻了既有决策**（需要一个地方说明"推翻了哪一条、为什么"）；
> 2. **决策内容超出方案章节的承载范围**（例如涉及外部依赖、许可、合作）；
> 3. 方案文档**拆分之后**（见方案开头"拆分触发条件"）。
>
> 模板见本文件末尾。

## ADR 模板（新建独立文件时用）

```markdown
# ADR-00NN <决策标题>

- 状态：已定 / 待定 / 已废弃（被 ADR-00XX 取代）
- 日期：YYYY-MM-DD
- 决策者：<谁拍的板>
- 影响范围：<哪几个里程碑>

## 背景
<什么问题逼着我们做这个决定>

## 备选方案
1. <方案 A>：优点 / 代价
2. <方案 B>：……

## 决定
<选了哪个，一句话>

## 理由
<为什么；引用哪份实证（尖刺结论 / 源码位置 / 外部来源）>

## 后果
- 正面：……
- 负面 / 需要接受的代价：……
- 若将来要推翻：<触发条件>
```

## 纪律

1. **新决策先写 ADR，再改方案。**
2. **凡是会推翻已有 ADR 的改动，必须在新 ADR 里写明"推翻了哪一条、为什么"。**
3. **同一决策不得存在两个真源**——要么在方案里（本登记册只留索引），要么在独立 ADR 里（方案只留指针），**不许两处都写全文**。
