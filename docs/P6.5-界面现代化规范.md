# P6.5 · 界面现代化规范

> 本文件是制作规划的一部分。它约束 P6 的界面实现，并在后续阶段持续有效。
> 上游：《Minecraft 启动器 · 架构规划与路线图（v1.2 正式版）》P6 阶段。
>
> **适用范围**：只约束表现层（`Qul.Presentation`）与主题资源。
> **不动领域层**，不改业务逻辑。若必须触及表现层之外，见 §7 的冲突清单与最小改动方案。

---

## 0. 硬约束（任一违反即视为未达标）

| # | 约束 |
|---|---|
| 1 | 主程序 ≤ 5 MB（目标 1–3 MB）；单文件绿色版；不落地临时目录 |
| 2 | 冷启动 ≤ 800 ms（宽松 1.5 s）；空闲内存 ≤ 80 MB |
| 3 | **不引入** MahApps.Metro / HandyControl / MaterialDesignInXAML 等重型 UI 库 |
| 4 | 深色优先，且支持浅色与跟随系统 |
| 5 | 不使用实时模糊、亚克力、重阴影、持续动画、复杂渐变 |
| 6 | 动效只用 Opacity 与 RenderTransform，时长 150–250 ms，**不做 Layout 动画** |
| 7 | 日志列表必须虚拟化；耗时操作不得阻塞 UI 线程，且可取消 |
| 8 | 高 DPI、窗口最小尺寸、Tab 键盘导航、焦点可视、屏幕阅读器 AutomationProperties |
| 9 | 离线账户启动前**强制**出现"无法进入正版验证服务器"的告知，不可默认跳过 |
| 10 | 素材一律自制矢量或系统图标，来源可追溯；不冒用 Mojang / Minecraft 官方品牌 |

## 1. 为什么不用重型 UI 库

决策不依赖精确数字，所以下面给的是**量级估计**（未在本机实测），以及不依赖量级的结构性理由。

| 库 | 体积量级 | 冷启动影响 | 内存影响 | 许可 |
|---|---|---|---|---|
| MahApps.Metro 2.x（+ ControlzEx） | ≈ 2.0–2.5 MB | 合并上千条资源字典，BAML 解析 +80–200 ms | +8–20 MB | MIT |
| HandyControl | ≈ 3.0–3.5 MB | 资源字典更大，+150–300 ms | +15–30 MB | MIT |
| MaterialDesignInXAML（+ Colors） | ≈ 3.0 MB | 含涟漪与持续动画，+150 ms 起 | +15 MB | MIT |

**结构性理由（这才是决定性的）**：

1. 这些库都会在启动时**把整套主题字典合并进来并解析 BAML**。我们的预算里冷启动只有 800 ms，
   而启动器真正要做的事是"读配置 → 探测 Java → 显示界面"。
2. 每个库都带来额外的 DLL，而本项目的目标是单文件——多一个 DLL 就多一份合并与启动开销。
3. **我们总共只需要约 12 个控件模板。** 自己写大约 600 行 XAML，零依赖、零启动开销、完全可控。

**结论：不引入。** 全部用原生 WPF 实现。

> 若将来确实需要引入，必须先补一张实测表（体积 / 冷启动 / 内存 / 许可四项都实测），
> 并同时给出不引入的替代方案，否则不予合入。

### 2.2 字体与字号

字体族只用**系统字体**：`Microsoft YaHei UI, Segoe UI, Arial`。
不打包任何字体文件（体积 + 许可双重考虑）。

| 语义键 | 字号 | 字重 | 用途 |
|---|---|---|---|
| `Font.Display` | 26 | SemiBold | 品牌区标题 |
| `Font.Title` | 19 | SemiBold | 区块标题 |
| `Font.Subtitle` | 15 | SemiBold | 卡片标题 |
| `Font.Body` | 13 | Normal | 正文 |
| `Font.BodyStrong` | 13 | SemiBold | 强调 |
| `Font.Caption` | 11 | Normal | 辅助说明 |
| `Font.Mono` | 12 | Normal | 日志（Consolas） |

行高统一 1.45 倍。中文不用斜体（渲染差）。

### 2.3 间距

尺度：`2 / 4 / 8 / 12 / 16 / 24 / 32 / 48`。
卡片内边距 `16`，卡片间距 `12`，区块间距 `24`，窗口边距 `24`。
**不使用尺度外的值**——随手写 `Margin="7"` 是界面显得业余的主要原因。

### 2.4 圆角

| 语义键 | 值 | 用途 |
|---|---|---|
| `Radius.Small` | 4 | 输入框、按钮、列表项 |
| `Radius.Medium` | 6 | 卡片 |
| `Radius.Large` | 8 | 浮层、抽屉 |
| `Radius.Pill` | 999 | 状态徽标 |

### 2.5 描边与"阴影"

**默认不用阴影。** 层次靠"表面色差 + 1px 描边"建立，这在深色下比阴影更清晰，也更快。

确实需要浮起感时，只允许一个极轻的阴影：
`BlurRadius=10, ShadowDepth=1, Opacity=0.15, Color=#000000`，且只用于弹出层。
**禁止**多层叠加阴影、大范围模糊、发光。

### 2.6 动效

| 语义键 | 时长 | 用途 |
|---|---|---|
| `Duration.Fast` | 120 ms | 悬停、按下 |
| `Duration.Normal` | 180 ms | 展开/折叠、状态切换 |
| `Duration.Slow` | 240 ms | 抽屉 |

缓动：`CubicEase EaseOut`。

**只允许动这三类属性**：`Opacity`、`TranslateTransform.Y`、`ScaleTransform.ScaleX/Y`。

**绝不动**：`Width` / `Height` / `Margin` / `Padding` / `FontSize` / `GridLength`——这些触发 Layout 重算。

**禁止持续动画**（旋转加载圈除外，且必须是离散帧而非连续变换）。

**时长不放在资源字典里。** `Storyboard` 的 `Duration` 在解析时就被烘焙进模板，
运行期改字典对它毫无影响——所以"换令牌关动画"这条路是死的。
时长由标记扩展提供：`Duration="{qul:Motion Fast|Normal|Slow}"`，
它在解析期决定取值，并尊重系统的"减少动态效果"（关闭时归零）。

**尊重系统"减少动态效果"**：`SystemParameters.ClientAreaAnimation` 为 false 时，所有时长归零。
这不是可选项——前庭功能敏感的用户会因此不适。

### 2.7 组件状态矩阵

每个交互控件必须覆盖：**Normal / Hover / Pressed / Focused / Disabled**，列表项另加 **Selected**。

| 控件 | Hover | Pressed | Focused | Disabled |
|---|---|---|---|---|
| 主按钮（Filled） | `Accent.Hover` | `Accent.Pressed` | 外描边 2px `Stroke.Focus` | `Stroke.Subtle` 底 + `Text.Disabled` |
| 次按钮（Subtle） | `Surface.RaisedHover` | `Surface.Inset` | 同上 | 同上 |
| 文本按钮 | 文字转 `Text.Primary` | — | 同上 | `Text.Disabled` |
| 危险按钮 | `Danger` 加深 | — | 同上 | 同上 |
| 输入框 | 描边转 `Stroke.Strong` | — | 描边 2px `Stroke.Focus` | `Surface.Inset` 底 |
| 列表项 | `Surface.RaisedHover` | — | 同上 | — |
| 面板（预检卡片） | — | — | — | — |

**焦点必须可见**：自绘模板最常见的失误就是把焦点视觉做没了。
每个模板都要显式写出 Focused 状态，且焦点环不能只靠颜色（同时改变描边粗细）。

## 3. 资源字典：文件结构与键命名

```
src/QinmoUltimateLauncher/Presentation/Theme/
  Tokens.xaml            与主题无关：间距 / 圆角 / 字号 / 时长 / 描边粗细
  Palette.Dark.xaml      深色语义色
  Palette.Light.xaml     浅色语义色
  Icons.xaml             自制矢量图标（Geometry）
  Controls.Buttons.xaml  按钮四层级
  Controls.Inputs.xaml   TextBox / ComboBox / CheckBox / ScrollBar / ProgressBar
  Controls.Surfaces.xaml Card / Divider / SectionHeader / InfoBar / Badge

  以上字典**由 App.xaml 扁平合并**，不再有中间的 Theme.xaml 聚合层。
  原因见 §7 冲突 9：模板里延迟解析的 StaticResource 在 ApplyTemplate 时按元素树向上查找，
  中途嵌在别的字典里找不到，Tokens 与 Icons 必须直接位于应用资源。
```

**全部以 `Page` 编译进程序集**（BAML），不落任何松散文件——与单文件方案天然一致，
也**不需要** Costura/ILmerge 额外处理。

### 键命名约定

| 前缀 | 含义 | 例 |
|---|---|---|
| `Qul.Brush.*` | 语义画刷 | `Qul.Brush.Surface.Raised` |
| `Qul.Size.*` | 尺寸 / 字号 / 描边 | `Qul.Size.Font.Body` |
| `Qul.Thickness.*` | 内边距 | `Qul.Thickness.Card` |
| `Qul.Radius.*` | 圆角 | `Qul.Radius.Medium` |
| `Qul.Duration.*` | 时长 | `Qul.Duration.Normal` |
| `Qul.Style.*` | 控件样式 | `Qul.Style.Button.Primary` |
| `Qul.Icon.*` | 图标几何 | `Qul.Icon.Play` |

### 静态与动态资源

- **颜色、画刷一律用 `DynamicResource`** —— 这样运行期换调色板才能生效。
  用 `StaticResource` 的会在换主题时"卡"在旧颜色上，这是主题切换最常见的 bug。
- 尺寸、圆角、字号用 `StaticResource`（不参与换主题，用静态省一次查找）。

## 4. 页面结构

MVP 单页主流程，纵向三段 + 底部抽屉：

```
┌─ 品牌 / 状态区 ─────────────────────────────────────────┐
│  Qinmo Ultimate Launcher        [主题▾]  [数据目录] [关于] │
│  一句话状态：共 917 个版本；最新正式版 26.3                │
├─ 主区（两栏）──────────────────────────────────────────┤
│ ┌ 左：配置卡片 ──────┐ ┌ 右：预检 + 进度 ─────────────┐ │
│ │ 版本        [▾][刷新]│ │ 启动前预检                  │ │
│ │ 身份来源    [▾]      │ │  ▸ 能力告知卡片（可确认）    │ │
│ │ 离线账户名  [____]   │ │  ▸ 阻断项卡片（红）          │ │
│ │ 目标服务器  [____]   │ │ ─────────────────────────── │ │
│ │ 内存        [—●——]   │ │ 阶段：解析/下载/校验/解压/启动│ │
│ └────────────────────┘ │ [■■■■■■□□□□]  62%           │ │
│                        └─────────────────────────────┘ │
├─ 底部操作条 ──────────────────────────────────────────┤
│  [日志 ▴]                    [复制诊断] [取消] [ 启 动 ] │
└───────────────────────────────────────────────────────┘
```

### 层级与主次

- **主操作**：`启动` —— Filled 主按钮，视觉权重最高。
- **次要操作**：`取消`、`复制诊断信息` —— Subtle 按钮。
- **文本操作**：`刷新`、`打开数据目录`、`主题` —— 文本按钮。
- **危险操作**：`删除实例`（后续阶段）—— Danger 按钮，且需要二次确认。

### 身份来源必须始终可见

当前来源在配置卡片中**常驻显示**，且每一项都带一句能力说明：

| 来源 | 说明文案 | 可用性 |
|---|---|---|
| 微软正版 | 使用你的微软账户登录 | 受 C1–C4 门禁；未满足时**可见但不可用**，并显示缺什么 |
| 离线账户 | 仅在本机有效，无法进入正版验证（online-mode）服务器 | 始终可用 |
| 第三方验证 | 该来源默认关闭，当前版本不提供 | 默认关闭 |

### 进度五阶段

`解析 → 下载 → 校验 → 解压 → 启动`。
每一阶段有独立的状态（未开始 / 进行中 / 完成 / 失败），当前阶段高亮。
进度条在有总量时显示确定进度，无总量时显示不确定态。

### 错误提示

InfoBar 风格，常驻在内容区顶部，**必须同时包含**：

1. 人话提示（`ErrorCodes.Hint`）
2. 错误码（`ErrorCodes.Id`，可选中复制）
3. `复制诊断信息` 按钮

只弹"启动失败"四个字是不合格的。

### 日志抽屉

可折叠，展开高度可控。**必须虚拟化**（`ListBox` + `VirtualizingStackPanel`，
`ScrollUnit="Pixel"`，`VirtualizationMode="Recycling"`），支持选中复制与"复制全部"。

## 7. 与现有架构的冲突点与最小改动方案

| # | 冲突 | 最小改动方案 | 触及层 |
|---|---|---|---|
| 1 | **日志不可虚拟化**：现 `MainViewModel` 把日志拼成一个大字符串绑到只读 `TextBox`，无法虚拟化 | 改为 `ObservableCollection<LogLine>` + 虚拟化 `ListBox`（`ScrollUnit=Pixel` + `Recycling`），保留"复制全部"。行数上限 5000，超出丢弃最早 | Presentation |
| 2 | **进度无法表达阶段**：现管线用 `IProgress<string>`，只有自由文本 | Infrastructure 增加 `LaunchStage` 枚举与 `LaunchProgress(Stage, Message, Completed, Total)`，管线改为 `IProgress<LaunchProgress>`。**领域层不动** | Infrastructure |
| 3 | **主题切换需要动态资源**：现有 XAML 全是硬编码十六进制色 | 全部改为 `DynamicResource` 语义键；`ThemeManager` 运行期替换 `MergedDictionaries[0]` | Presentation |
| 4 | **高 DPI**：net48 默认是系统级 DPI 感知，4K 缩放下会模糊 | 新增 `app.manifest` 声明 `PerMonitorV2`；窗口布局使用与设备无关单位（WPF 默认即是） | 项目文件 |
| 5 | **减少动态效果** | 动效时长统一取自一个转换器；`SystemParameters.ClientAreaAnimation` 为 false 时返回 0 | Presentation |
| 6 | **自绘模板会丢无障碍信息** | 每个 `ControlTemplate` 配套补 `AutomationProperties.Name` / `HelpText`；`ComboBox` 自绘时保留 `IsEditable` 语义 | Presentation |
| 7 | **单文件与资源字典** | 主题 XAML 以 `Page` 编译为 BAML 打进程序集，天然满足；无需额外合并步骤 | 无 |
| 8 | **窗口最小尺寸与高 DPI** | 现有 `MinWidth=900 / MinHeight=580` 在 200% 缩放下等价于 450×290 逻辑像素，内容会挤坏；改为 `MinWidth=760 / MinHeight=560`，日志抽屉由固定高度改为 `MinHeight` 以便随窗口收缩 | Presentation |
| 9 | **模板内 StaticResource 找不到资源** | 模板内容里的 `{StaticResource}` 在 `ApplyTemplate` 时才按元素树向上查找，嵌在中间层字典里会抛 XamlParseException。资源必须在 `App.xaml` 里**扁平**合并，且 `Tokens` / `Icons` 直接位于应用资源 | 项目文件 |
| 10 | **只读属性被 TwoWay 绑定** | `RangeBase.Value` 默认 TwoWay，绑到只有私有 setter 的属性会在窗口构造时抛 InvalidOperationException。显式写 `Mode=OneWay` | Presentation |

**冲突 1、2 是必须做的改动**，其余是新增。**没有任何一项需要改领域层。**

## 8. 验收记录

| 项 | 标准 | 实测 |

### 一条环境教训（会反复咬人）

**PowerShell 进程默认是 DPI 不敏感的。** 在 150% 缩放下：
`GetWindowRect` 返回**逻辑**坐标（1120×820），而 `CopyFromScreen` 用的是**物理**坐标。
于是截图只取到了真实窗口（1680×1230）的左上角一块，看起来像"右侧溢出、底部按钮条消失"，
实际上布局一直是对的。截图前必须先 `SetProcessDPIAware()`。

## 附：下载可见性（实测驱动的一次补充）

**触发原因是一次数出来的实测，不是一个想法。** 在只放了 exe 的空目录里冷装 1.7.10，
15 分钟下了 596 个文件 / 116.2 MB 仍未跑完；而界面上从头到尾只有一行"开始获取所需文件…"。

带宽差是环境问题，**"看不出还要多久、也看不出是否在动"是产品问题**。

### 实现

`Application/Launch/ThroughputEstimator` 把"累计已传字节"的时间序列变成速率与剩余时间：

| 取舍 | 理由 |
|---|---|
| 速率取**窗口内（30 秒）平均**，不是相邻两次采样的瞬时值 | 瞬时值随每次回调剧烈跳动，看起来像坏了 |
| 算不出速率或不知总量时，剩余时间返回 null | **宁可说"剩余时间未知"，也不要编一个数出来** |
| 只有字节数**变大**才重置停滞计时 | 引擎重试/换源时会重复上报同一个数字，那正是"卡住"该被看见的时刻 |
| 停滞时**刻意不显示剩余时间**，改说"已 N 秒没有新数据，仍在重试" | 那一刻的速率已经不可信，继续报数只会让人以为马上就好 |

`LaunchProgress` 新增 `BytesCompleted` / `BytesTotal` 两个结构字段——
在此之前字节数**只以文本形式出现在 message 里**，界面拿不到可计算的值。

界面在进度条下方显示 `ProgressDetail`，如「12 KB/s · 剩余约 8 分 20 秒」。

### 一个被自己抓到的无障碍缺陷

初版给这一行设了 `AutomationProperties.Name="下载速度与剩余时间"`。
那会让屏幕阅读器**永远念固定文案，念不出真正的速度**——
恰恰废掉了这一行存在的意义。改为不设 Name（TextBlock 的可访问名称默认就是文本），
并用 `AutomationProperties.LiveSetting="Polite"` 让变化被播报而不抢焦点。
