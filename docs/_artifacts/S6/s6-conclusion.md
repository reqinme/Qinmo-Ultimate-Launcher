> **执行**：`qul java`（真实工具，非一次性脚本）· 2026-10-01 · M0 尖刺 S6
> **产物**：`s6-discovery.json`（含每个候选的来源、被跳过项及原因）
> **回填**：`docs/M0-尖刺任务书.md` S6 结论槽

## 1. 结论

```
发现 Java 数量：12    误报/漏报：0 / 0（并另有 26 处被跳过、逐条附原因）
五场景选择正确率：5/5     缺 Java 提示：☑可操作
```

## 4. 两处**实测才暴露**的修正（本项真正的收获）

### 4.1 Oracle 的"启动器存根"被选中过

**第一次跑**，Java 8 被选成了：

```
C:\Program Files (x86)\Common Files\Oracle\Java\java8path\java.exe
```

它**能用**——所以五场景当时也是 5/5。**但它是错的**：

> `Common Files\Oracle\Java\*path\java.exe` **不是运行时**，
> 而是一个**按注册表转发到某个 JRE 的启动器**。

**后果正是 S6 要消灭的那类失败**：用户在别处改了注册表 → 我们选的 Java 变了 →
游戏起不来 → **而用户与我们都看不出原因**。

**修法**：选择时**优先非存根候选**，只有当满足项**全是存根**时才退回存根，
**并在 `reason` 里写明"可用但不理想，建议安装独立 JDK"**。

> **这条单靠"5/5 通过"是看不出来的。**
> 如果只按"选出来了吗"判定，这一项会以满分通过，而缺陷留在里面。

### 4.2 目录名匹配把 Microsoft 全家桶当成了 Java

第一版用 `"Microsoft"` 作为厂商目录名，于是扫了
`Microsoft Office`、`Microsoft SQL Server`、`Microsoft Visual Studio`……**没有一个是 Java**。

**修法**：厂商名只在"它不可能同时是非 Java 产品名"时才可用；
`Microsoft` 改为 `Microsoft\jdk`。

### 4.3 顺带：`-version` 的输出去 stderr，不在 stdout

第一版只读 stdout，得到空串。**这一条已写进代码注释**，
因为它是"探测失败但没有报错"的经典形态。

## 5. 选择判据（每一步都写进代码注释，因为顺序错了用户看到的是"随机失败"）

| 序 | 判据 | 理由 |
|---|---|---|
| 1 | 满足最低版本 | 硬门槛 |
| 2 | **非存根优先** | §4.1 |
| 3 | 64 位优先 | 32 位装不了现代版本的内存需求；32 位只在无 64 位可选时退回，**并说明风险** |
| 4 | **同档选主版本最低** | 能用 17 跑就别上 21——**更高版本有时会让老模组出问题，而用户看不出是这个原因** |
| 5 | 版本串、路径依次排序 | **结果必须确定**（同机同输入同输出），否则问题无法复现 |

## 6. 缺 Java 的提示（S6 第 4 条，**有独立单测**）

方案要求的形式是"需要 Java 21，未找到；已找到 Java 8 与 17"。
所以提示必须做三件事：**说需要什么、说本机有什么、说下一步做什么。**

| 场景 | 提示 |
|---|---|
| 一个 Java 都没有 | 「需要 Java 21 或更高，但本机没有检测到任何 Java。请安装 ……，或在设置里手动指定 Java 路径。」 |
| 有 Java 但都不满足 | 「需要 Java 21 或更高，本机未找到；已找到 Java 8 与 Java 17。请安装 ……」 |

**"只说未找到 Java"被明确禁止**——那不是提示，是把问题丢回给用户。

## 7. 探测覆盖（四路并行）

| 来源 | 说明 |
|---|---|
| **注册表** | `HKLM\SOFTWARE\JavaSoft` 的 `JRE`/`JDK`/`Java Runtime Environment`/`Java Development Kit`，**含 `WOW6432Node`**（32 位视图） |
| **环境变量** | `JAVA_HOME` / `JDK_HOME` / `JRE_HOME` |
| **PATH** | 逐段找 `java.exe` / `javaw.exe` |
| **常见目录** | `Program Files(×2)` 与 `LOCALAPPDATA` 下的 Adoptium / Java / Corretto / Zulu / BellSoft / Semeru / AdoptOpenJDK / `Microsoft\jdk` |

**用 `reg.exe query` 而不是引入 `winreg`**：这是尖刺，多一条依赖就多一条要审的许可，
而 `reg` 是系统自带、失败时返回非零可判。

**26 处"被跳过"逐条记录了原因**（例如"注册表登记的 JavaHome 下没有 bin\java.exe"）。
这一项是刻意保留的：S6 要求"无漏报"，
而**"某路径被跳过"与"那个路径不存在"是两件事——没有这份记录，漏报就查不出来**。

## 8. 已知限制（S6 的"不通过怎么办"预授权了这条）

| 限制 | 兜底 |
|---|---|
| **绿色版 / 解压版不注册**的 Java 扫不到（只扫一层深） | **手动指定路径**（S6 明确要求本轮可用） |
| 非 Windows 平台未测 | 本机是 Windows，属环境事实 |
| `javaw.exe` 与 `java.exe` 去重为同一个运行时 | 有意：它们同目录、同运行时 |

## 10. 分层（这一项的落点本身就验证了架构）

| 层 | 放什么 | 为什么 |
|---|---|---|
| `qul-core::java` | **版本要求与选择规则** | **纯规则、零 IO** → 可穷举测试（12 项全绿） |
| `qul-infra::java` | **探测与版本查询** | 需要注册表与子进程 → 只能实测 |
| `qul-app` | `java_choice_for`（转接） | **界面与 CLI 必须共用同一个顺序**，不许两处各写一遍 |

> `qul-core` 的架构测试（`tests/guardrails.rs`）会拒绝在这一层出现
> `std::fs` / `std::process`——所以这个切分**不是约定，是被强制的**。
