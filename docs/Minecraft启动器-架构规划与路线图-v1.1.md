## 0. 设计原则

| 原则 | 含义 | 反面案例（要避免的） |
|---|---|---|
| 启动器只是"编排器" | 只做解析、获取、组装、拉起，不实现游戏逻辑 | 自己写资源加载、自己改 jar |
| 一切外部输入都不可信 | 版本 JSON、远端清单、下载内容全当脏数据 | 直接反序列化就信、不校验哈希 |
| 界面与引擎解耦 | UI 挂了不影响命令行启动；引擎可被 CLI/测试直接调用 | 逻辑写在 XAML 事件处理里 |
| 一个版本 = 一份不可变"启动计划" | 先算出完整计划，再执行；可预演、可导出、可复现 | 边下边拼参数，失败无法复现 |

## 1. MVP 范围与推荐实现顺序

### 1.1 MVP 边界（明确"做"与"不做"）

| 归类 | MVP 内 | MVP 外（延后至 P8+） |
|---|---|---|
| 版本 | 官方 Release 正式版，单一安装实例 | 快照、旧版 Alpha/Beta、多实例并存（P8） |
| 身份来源 | 微软正版账户；离线账户（须明确告知"无法进入正版验证服务器"） | 第三方验证（P10，可选、默认关闭）；多账户切换 |
| 内容 | 纯原版，无 mod / 无资源包 | Fabric / Forge / NeoForge / Quilt、整合包（P9） |
| Java | 本机 Java 探测 + 用户手动指定路径 | 自动下载运行时（P10，可选、默认关闭） |
| 内容来源 | 仅官方源 | 镜像源（P10，可选、默认关闭、用户显式启用） |
| 运行 | 组装参数、拉起进程、回收退出码与日志 | 性能调优、内存自动推荐、崩溃自动归因 |
| 界面 | 一个页面：选版本 → 选身份来源 → 启动 + 日志窗 | 皮肤、新闻、主题、多语言 |
| 分发 | 单文件绿色版，本地运行 | 自动更新、统计遥测、崩溃上报 |

> **MVP 成功定义一句话**：一个玩家，双击一个 exe，选择身份来源并登录（微软正版或离线），点一次启动，能进到游戏主菜单；若使用离线账户，界面必须明确提示其无法进入正版验证服务器。

### 1.2 推荐实现顺序（每步都可独立验证，不要跳步）

| 序 | 里程碑 | 为什么排这个位置 | 该步结束时的可验证状态 |
|---|---|---|---|
| 1 | 地基：路径/配置/日志/异常规范 | 后面所有模块都依赖它，改一次代价最大 | 能定位游戏目录、写结构化日志、异常有统一格式 |
| 2 | 版本清单获取与解析 | 启动链路的"数据源"，纯逻辑、最易测 | 能列出所有正式版、能取到指定版本的完整 JSON |
| 3 | 下载器（并发/校验/续传/缓存） | 全链路最大的失败源，必须最先做扎实 | 断网续传、坏文件自动重下、重复请求命中缓存 |
| 4 | Java 运行时探测与选择 | 决定能否启动，与网络无关，可离线验证 | 正确识别 Java 主版本并匹配版本要求，可手动指定 |
| 5 | 启动计划组装 + 进程管理 | 前四步的汇聚点，此时可用离线身份跑通全链路 | 能拉起原版客户端并看到游戏窗口 |
| 6 | 身份来源接入（离线 + 微软正版） | 先以离线账户（本地生成身份、无网络依赖）打通链路，再接入微软正版流程；避免认证环节阻塞前五步 | 离线账户可启动并带明确告知；微软正版账户可正常进入游戏 |
| 7 | UI 串联与错误诊断 | 界面前置于此，是为了不把时间浪费在改 UI 上 | 全流程一次点通；失败有人话级提示且能判断账户与服务器兼容性 |
| 8 | 发布工程（单文件、体积、冷启动） | 收尾工程化，避免过早优化 | 单 exe 可分发，五项软预算完成实测 |

> **关键顺序纪律**：第 6 步之前，第 5 步的链路验证统一使用 **离线账户** 作为身份提供方——它本身就是 MVP 内合法可交付的身份来源之一，不需要临时桩代码，也天然规避了认证环节对网络与浏览器环境的依赖。

## 2. 分阶段路线图（目标 / 任务 / 交付物 / 验收）

### P0 地基与规范

| 项 | 内容 |
|---|---|
| 目标 | 建立不可动摇的目录、配置、日志、异常约定 |
| 关键任务 | 分层骨架（UI/应用/领域/基础设施）；`.minecraft` 布局兼容；配置读写与迁移；结构化日志（含启动会话 ID）；统一错误码 |
| 交付物 | 目录规范文档；配置 Schema；错误码清单；日志字段字典 |
| 验收标准 | 全新机器首次运行能自动建目录；配置损坏时能降级而非崩溃；任一失败都有唯一错误码 + 人话提示 |

### P1 版本元数据

| 项 | 内容 |
|---|---|
| 目标 | 完整、正确地理解"一个版本是什么" |
| 关键任务 | 版本清单索引解析（含 latest/release/snapshot）；版本 JSON 解析；`inheritsFrom` 继承合并；`rules` 规则求值（系统/架构/特性）；新旧两种参数写法兼容；`javaVersion` 与 `downloads` 结构解析 |
| 交付物 | 版本元数据模型说明；继承与规则求值规则书；兼容性测试清单（跨多个年代版本） |
| 验收标准 | 任取 1.7.10 / 1.12.2 / 1.16.5 / 最新正式版四个版本，解析出的库列表、主类、参数与官方启动器一致；遇到未知字段不崩溃（前向兼容） |

### P2 下载与缓存（已调整）

| 项 | 内容 |
|---|---|
| 目标 | 任何资源都能"最终正确落盘"，且不重复劳动；来源可替换而不影响正确性 |
| 关键任务 | 库/客户端 jar/资源索引/资源对象四类下载通道；**SHA-1 校验基准恒定取自官方元数据**；并发与限速；断点续传；失败重试与退避；缓存目录与垃圾回收；磁盘空间预检；**引入"来源策略"抽象**（`IContentSource` 多实现），MVP 仅注册官方源 |
| 交付物 | 下载任务模型；缓存布局文档；重试与校验策略说明；**来源策略说明（含"校验基准永不来自镜像"这条硬约束）** |
| 验收标准 | 拔网线中途恢复后能续传完成；故意损坏一个已缓存文件能被检出并重下；重复启动同一版本不产生冗余网络请求；单文件失败不影响整体可重试；**MVP 阶段配置中不存在镜像开关，代码路径中不存在"信任远端提供哈希"的可能** |

### P3 Java 运行时（已调整）

| 项 | 内容 |
|---|---|
| 目标 | 找得到、选得对、说得清；为未来的运行时来源扩展留好接口边界 |
| 关键任务 | 常见安装位置与 PATH 探测；版本号解析（含旧式 1.8.0_x 与新版 17/21）；按 `javaVersion.majorVersion` 匹配；架构匹配（x64/arm64）；用户手动指定覆盖；不可用时的明确指引；**`IRuntimeProvider` 按多实现设计并声明能力（是否可下载、是否需许可告知）** |
| 交付物 | Java 探测规则表；候选排序策略；不可用时的提示文案；**运行时来源能力矩阵（本机探测 / 手动指定 / 未来自动下载）** |
| 验收标准 | 本机存在多个 Java 时自动选中满足该版本要求的最新可用者；用户手动指定的路径优先生效且可校验有效性；无可用 Java 时不报堆栈而是给出可执行指引；**MVP 内不包含任何自动下载行为，接口层面的扩展点已就位** |

### P4 启动计划与进程管理

| 项 | 内容 |
|---|---|
| 目标 | 把元数据 + 身份 + Java + 配置，变成一条可复现的启动命令 |
| 关键任务 | natives 分类器筛选与解压；类路径顺序；JVM 参数与游戏参数分组合并；占位符替换；工作目录设定；进程启动、标准输出捕获、退出码处理；子进程生命周期与"启动器关闭后游戏是否存活"策略 |
| 交付物 | 启动计划模型（可序列化，用于排障与复现）；参数组装规则说明；退出码含义表 |
| 验收标准 | 计划可导出为人类可读文本用于比对；同一输入两次生成的计划逐字节一致；游戏退出后启动器正确回收资源并保留完整日志 |

### P5 身份来源（一致性调整）

| 项 | 内容 |
|---|---|
| 目标 | 合规地完成多来源身份获取，并对每种来源的能力边界做出准确告知 |
| 关键任务 | 微软 OAuth 授权流程（浏览器/设备码二选一）；Xbox Live 与 Minecraft 服务链路换取游戏身份；令牌过期刷新；**离线账户实现（本地生成身份标识，无网络验证）**；账户信息缓存与加密存储（系统凭据保护）；登出与撤销；失败分类（用户取消 / 网络 / 无游戏所有权）；**UI 对离线与第三方来源展示能力限制说明** |
| 交付物 | 认证流程图与状态机说明；令牌存储安全说明；错误分类表；**身份来源能力与限制说明表** |
| 验收标准 | 冷启动可免二次登录（令牌有效期内）；令牌过期自动静默刷新；无游戏所有权的账户给出明确提示而非崩溃；登出后本机不残留明文令牌；**选择离线账户时，启动前必须出现"无法进入正版验证服务器"的显式告知，且该告知不可被默认跳过** |

### P6 界面与诊断（一致性调整）

| 项 | 内容 |
|---|---|
| 目标 | 让失败可被用户理解、可被你自己复现 |
| 关键任务 | 单页主流程；进度与阶段细分（解析/下载/校验/解压/启动）；可折叠日志窗；"复制诊断信息"（版本、Java、参数、错误码、时间线）；启动前预检（磁盘、Java、账户、网络）；**预检需判断"当前身份来源 + 目标服务器"是否可能被拒绝（离线进正版验证服务器、第三方验证目标不匹配等）** |
| 交付物 | 交互流程说明；诊断信息模板；预检清单（含身份来源与服务器兼容性判定） |
| 验收标准 | 任意一类失败，用户不做任何额外操作即可复制出可定位问题的信息；UI 在下载/校验/启动期间不假死，可取消；**以离线账户连接正版验证服务器时，在启动前即给出可理解的拒绝风险提示** |

### P7 发布工程（已调整）

| 项 | 内容 |
|---|---|
| 目标 | 单文件、体积可控、冷启动达标、可更新，并以实测数据校准软预算 |
| 关键任务 | 依赖合并为单 exe 的策略（资源合并型方案优先，避免解压到临时目录拖慢首启）；体积预算控制；签名与杀软误报评估；便携/安装两态；更新策略（自替换 or 引导器）；**按下列软预算做实测并记录偏差归因** |

**软预算表（C# + WPF + net48 口径）**

| 指标 | 目标值 | 宽松上限 | 测量条件 |
|---|---|---|---|
| 主程序体积 | 1–3 MB | ≤ 5 MB | 发布产物主 exe，不含用户数据与缓存 |
| 冷启动到可交互 | ≤ 800 ms | ≤ 1.5 s | 进程创建 → 主界面可点击；不含首次下载与首次登录 |
| 空闲内存 | — | ≤ 80 MB | 主界面静置 30 s 的工作集 |
| 首启落地行为 | 不落地临时目录 | 不落地临时目录 | 首启过程中不产生解压到临时目录的行为 |
| 首启与二次启动差异 | — | ≤ 200 ms | 同一机器、同一版本、缓存已就绪条件下的差值 |

| 项 | 内容 |
|---|---|
| 交付物 | 体积与冷启动实测报告；分发形态说明；更新策略说明；**偏差归因说明（工程实现问题 vs 架构问题）** |
| 验收标准 | 五项指标完成实测并有原始数据；未达标项给出归因结论与处置计划；无被杀软大面积误报；更新失败可回退到旧版本 |
| 预算纪律 | 软预算仅在 P7 用于校准。**P0–P6 阶段不得为了压低体积或启动时间而牺牲分层、可测试性与扩展性**；若两者冲突，以架构正确性优先，并在 P7 报告中记录该权衡 |

### P8+ 扩展阶段（已重写）

> 定位：P0–P7 是第一阶段，先把 MVP 打磨到验收通过。以下为第二阶段及以后，**顺序即优先级**。

#### P8 多实例与实例管理（第二阶段 · 第一优先）

| 项 | 内容 |
|---|---|
| 目标 | 从"一个版本"演进到"多个可启动实例并存" |
| 关键任务 | 实例模型（版本 + 身份来源偏好 + Java + 内存 + 目录）；实例隔离的数据目录；实例的创建/复制/删除/迁移；主界面从"选版本"改为"选实例"；全局配置与实例配置的层级合并规则 |
| 交付物 | 实例模型说明；目录隔离布局文档；配置层级合并规则 |
| 验收标准 | 两个实例使用不同版本与不同 Java 互不干扰；删除实例不影响其它实例与共享缓存；MVP 的单实例体验退化为"仅一个实例"的特例而非另一条代码路径 |

#### P9 模组加载器（第二阶段 · 第二优先）

| 项 | 内容 |
|---|---|
| 目标 | 在实例之上支持加载器安装与启动，保持"加载器只是版本元数据的一种合成来源"这一心智模型 |
| 关键任务 | 加载器版本元数据获取与合成（含 `inheritsFrom` 指向原版版本）；加载器库的下载与校验；启动参数差异处理；安装事务性（失败可回滚到安装前状态）；**Fabric 先行，Forge / NeoForge 后续** |
| 交付物 | 加载器合成规则说明；安装事务与回滚策略；加载器兼容矩阵 |
| 验收标准 | Fabric 实例可正常启动；加载器安装失败后实例回到可用的原版状态；加载器元数据源的差异被隔离在 `IContentSource` 实现内，不污染 P1 的原版解析逻辑 |

#### P10 可选能力（第二阶段 · 默认全部关闭，用户显式启用）

| 能力 | 任务要求 | 验收标准 |
|---|---|---|
| **Java 自动下载** | `IRuntimeProvider` 新增"可下载"实现；**只选许可允许再分发的 JRE 构建**；随附许可文本；运行时按需下载到用户数据目录；**绝不打包进主程序**；提供校验与卸载 | 默认关闭；启用后能自动获取满足版本要求的运行时；许可文本可被用户查看；关闭该能力后行为与 MVP 完全一致 |
| **镜像源** | `IContentSource` 新增镜像实现；来源可配置；UI 明示当前来源与风险；**所有校验基准仍取自官方元数据，镜像仅作字节传输通道**；提供一键回退官方源 | 默认关闭；启用需用户显式确认；镜像返回的清单与哈希不被采信为真源；关闭后行为与 MVP 完全一致 |
| **第三方验证** | `IAuthProvider` 新增第三方实现；默认关闭；启用时展示第三方服务条款与依赖说明；明确该来源不伪造官方会话、不接触官方验证接口；处理其可能要求的额外 JVM 参数注入 | 默认关闭；启用需用户显式确认；登录失败与服务不可用有明确分类提示；停用后不影响微软与离线来源的可用性 |

#### P11 基岩版可行性预研（第二阶段 · 只调研，零代码）

| 项 | 内容 |
|---|---|
| 目标 | 用一份决策报告回答"是否值得真正接入基岩版"，而不是先写代码再论证 |
| 关键任务 | 调研 Windows 基岩版的 **UWP/MSIX 分发与沙箱体系**；梳理启动器在其上可操控的空间（进程拉起、参数注入、实例隔离、模组注入各有多少自由度）；与 Java 版启动链路的复用度评估；合规与平台条款评估；给出明确的"接 / 不接 / 有条件接"结论与前置条件 |
| 交付物 | 基岩版可行性预研报告（含能力边界矩阵、复用度评估、合规结论、决策建议） |
| 验收标准 | 报告明确回答复用度与可操控性两个问题；给出可执行的决策建议；**预研过程中不产生任何基岩版相关代码或项目文件**；预研结论作为是否进入后续阶段的唯一依据 |
| 前置判断 | Windows 基岩版属 UWP/MSIX 体系，启动器可操控空间小、与 Java 版复用度低，因此**默认预期为"不接"或"仅做极有限的启动封装"**，需报告证实或推翻这一预期 |

## 3. Java 版启动链路（七个环节的要点与陷阱）

| 环节 | 必须做对的事 | 常见陷阱 |
|---|---|---|
| ① 账户认证 | 走官方授权流程拿到游戏档案；令牌加密存储；自动刷新；明确区分"未登录/无所有权/令牌失效"；**离线来源仅提供本地身份标识并在启动前告知其能力限制；第三方来源按其条款获取身份并可能需要额外 JVM 参数注入** | 明文存令牌；把刷新失败当登录失败；在 UI 线程做网络请求；**把离线身份当作可进入正版验证服务器** |
| ② 版本清单 | 先取索引再取版本详情；索引有缓存有效期；版本详情要落盘缓存但可强制刷新 | 每次启动都全量拉索引；把索引当版本详情用 |
| ③ 依赖下载 | 库按 `rules` 过滤后再下；注意 `natives` 分类器；客户端 jar 是独立下载项；全部校验 SHA-1；失败可重试可续传；**校验基准恒定取自官方元数据** | 忽略规则求值导致下了 Linux 库；跳过校验；路径含空格/中文未处理；信任镜像提供的哈希 |
| ④ 资源索引 | 资源索引与资源对象是两层；索引为映射表，对象按哈希前两位分目录；新版索引可能不含虚拟目录映射，需自行处理映射缺失场景 | 把索引直接当文件列表；忽略映射结构差异导致旧版本资源错位 |
| ⑤ natives 解压 | 按平台分类器挑选 natives 包；解压到独立目录并排除 META-INF；把该目录加入类路径；每次启动前清理或按版本隔离 | 直接把 natives 当普通库加进类路径；混用不同版本 natives 导致本地库冲突；不清理残留导致诡异崩溃 |
| ⑥ JVM/游戏参数 | 严格按版本 `javaVersion` 选 Java；JVM 参数（内存、编码、本地库路径）与游戏参数（用户名、UUID、令牌、版本、资源目录、资产索引 ID）分组管理；占位符替换必须严格匹配官方约定；处理新式 `arguments` 与旧式 `minecraftArguments`；**身份来源差异只在此环节体现为注入内容与附加参数的不同** | 参数里出现未替换占位符；内存设置超出机器物理内存；缺少资源索引 ID 导致游戏内模型/贴图异常；为第三方来源硬编码注入逻辑而非走提供方契约 |
| ⑦ 进程管理 | 独立工作目录；捕获 stdout/stderr 落盘；区分"启动器退出"与"游戏退出"；退出码映射为可读结论；异常退出保留上下文 | 用管道缓冲导致日志丢失；父进程结束时误杀游戏；不区分崩溃与正常退出 |

> **链路设计的核心产物**：一个可序列化的 **LaunchPlan**（版本、Java、类路径、natives 目录、JVM 参数、游戏参数、工作目录、环境变量、**身份来源类型与其注入项**）。它是排障、复现、对比、"只预演不启动"能力的唯一支点，MVP 阶段就要有。

## 4. 可扩展架构建议

### 4.1 分层与依赖方向

| 层 | 职责 | 允许依赖 |
|---|---|---|
| 表示层 | 交互、状态展示、日志呈现 | 应用层 |
| 应用层 | 用例编排：登录、安装、启动、取消、预检 | 领域层 + 抽象端口 |
| 领域层 | 纯模型与规则：版本、规则求值、启动计划、身份档案 | 无外部依赖（可纯单元测试） |
| 基础设施层 | HTTP、文件系统、压缩、Java 探测、凭据存储、进程 | 领域层定义的端口 |

依赖永远指向内层。**领域层不允许出现 HTTP 客户端、文件路径、命令行的字样。**

### 4.2 核心抽象

| 抽象 | 解决的问题 | 未来受益场景 |
|---|---|---|
| `IGameBackend`（游戏后端适配器） | "启动一个游戏"的统一契约：预检、安装/准备、启动计划、进程监控 | Java 版、基岩版（若 P11 结论为接）、其他游戏各实现一个 |
| `IAuthProvider`（身份提供方） | 登录、刷新、登出、档案获取、能力声明 | 微软正版、离线、第三方验证 |
| `IContentSource`（内容源） | 版本清单、库、资源、附加内容的统一获取与元数据 | 官方源、镜像源、未来内容平台 |
| `IRuntimeProvider`（运行时提供方） | 运行时探测、选择、能力声明（未来含获取） | 本机探测、手动指定、自动下载 |
| `IInstallation`（安装实例） | 一次"可启动的配置"：版本 + 加载器 + Java + 内存 + 目录 | 多实例、整合包、多后端并存 |

#### `IAuthProvider` 扩展契约

| 契约要素 | 说明 |
|---|---|
| 身份来源类型 | 微软 / 离线 / 第三方（枚举化，UI 与预检据此决策） |
| 是否在线验证 | 该来源是否需要联网校验；离线为否 |
| 启动时注入什么 | 用户名、UUID、访问令牌、用户类型标记、来源标识 |
| 是否需要额外 JVM 参数 | 第三方来源可能要求注入代理类参数；由提供方自行声明 |
| 能力声明 | 能否进入正版验证服务器、能否刷新、能否撤销、是否需加密存储 |
| 预检能力 | 能否判断"当前账户 + 目标服务器"是否可能被拒绝 |
| 令牌生命周期与安全 | 过期与刷新策略；令牌是否必须加密存储；登出与撤销语义 |

**身份来源能力对照（落地阶段与默认状态）**

| 来源 | 落地阶段 | 默认状态 | 在线验证 | 可进入正版验证服务器 | 额外 JVM 参数 | 合规要点 |
|---|---|---|---|---|---|---|
| 微软正版 | MVP（P5） | 可用 | 是 | 是 | 否 | 走官方授权流程，令牌加密存储 |
| 离线 | MVP（P5） | 可用，**强制告知限制** | 否 | **否** | 否 | 不伪造官方会话；UI 明示无法进入正版验证服务器 |
| 第三方验证 | P10 | **关闭** | 视服务而定 | 视服务条款而定，不保证 | 可能需要 | 默认关闭、显式启用、展示第三方条款；不接触官方验证接口 |

#### `IRuntimeProvider` 扩展契约

| 契约要素 | 说明 |
|---|---|
| 来源类型 | 本机探测 / 手动指定 / 自动下载 |
| 能力声明 | 是否可获取、是否需要许可告知、是否可卸载 |
| 许可合规标记 | 只有许可允许再分发的构建才可被"可获取"实现接受 |
| 选择策略 | 按版本要求的 Java 主版本 + 架构匹配 + 用户偏好排序 |
| 失效与回退 | 探测失败或下载失败时回退到手动指定或明确指引 |

**运行时来源实现矩阵**

| 实现 | 阶段 | 默认 | 说明 | 许可约束 |
|---|---|---|---|---|
| 本机探测 | MVP（P3） | 启用 | 扫描常见位置与 PATH，解析版本与架构 | 不涉及分发 |
| 手动指定 | MVP（P3） | 启用 | 用户指定路径，优先于自动选择 | 不涉及分发 |
| 自动下载 | P10 | **关闭** | 运行时按需下载到用户数据目录 | **只选许可允许再分发的 JRE 构建；附许可文本；绝不打包进主程序** |

#### `IContentSource` 扩展契约

| 契约要素 | 说明 |
|---|---|
| 来源类型 | 官方源 / 镜像源 |
| 能力范围 | 版本清单、版本详情、库、客户端、资源索引、资源对象 |
| 信任边界 | **清单与哈希的信任基准只能来自官方元数据；镜像仅是字节传输通道** |
| 用户可见性 | 当前生效来源必须在 UI 中可见 |
| 回退策略 | 可一键切回官方源；镜像失败不阻断官方源路径 |

**内容来源实现矩阵**

| 实现 | 阶段 | 默认 | 说明 | 风险 |
|---|---|---|---|---|
| 官方源 | MVP（P2） | 启用且唯一 | 存在性、正确性、许可最干净 | 速度受网络环境影响 |
| 镜像源 | P10 | **关闭** | 用户显式启用、来源可配置 | 投毒风险、条款风险、断供风险（详见 6.2） |

### 4.3 支撑性设计

| 设计 | 说明 |
|---|---|
| 能力声明而非能力假设 | 每个后端声明自己支持什么（是否支持 mod、是否支持多实例、是否支持离线、是否有资源索引）。UI 按能力渲染，而不是 `if (是Java版)` |
| 事件/进度总线 | 下载、校验、解压、启动各阶段统一上报进度与取消，UI 只订阅 |
| 一切耗时操作可取消 | 取消语义从 MVP 起就贯穿，后补成本极高 |
| 配置与状态分离 | 配置（用户意图）与状态（缓存、已装内容）分开存储，便于迁移与重置 |
| 契约测试 | 对每个后端实现跑同一套验收夹具（预检→准备→启动→回收） |
| 明确的"不做"边界 | 认证、版权素材、游戏逻辑一律不自己实现，只编排 |

### 4.4 非 MC 功能的预留方式

不要为"未来未知功能"提前造框架，只做两件事：**（1）** 应用层用"任务/用例"组织，新功能是一个新用例而非新窗口逻辑；**（2）** 主界面用"功能区/入口"注册表驱动，而非硬编码标签页。这两点足够，其余等真需求出现再抽象。

## 5. 基岩版与 Java 版启动差异

| 维度 | Java 版 | 基岩版（Windows） |
|---|---|---|
| 可执行形态 | JVM 进程 + jar/类路径 | 原生可执行程序（无 JVM） |
| 运行时依赖 | 需要匹配的 Java 运行时 | 通常依赖系统运行时组件，随包分发 |
| 版本与元数据来源 | 公开版本清单 + 版本 JSON | 无等价的公开启动清单，元数据来源完全不同 |
| 依赖模型 | 库 + natives + 资源索引，逐项下载校验 | 无"库/资源索引"概念，通常是整体包或应用包 |
| 启动方式 | 组装命令行参数拉起 | 启动应用/包，可能涉及应用容器与注册状态 |
| **分发与沙箱体系** | **绿色版目录，启动器可完全掌控文件与进程** | **UWP/MSIX 体系，受应用容器与平台沙箱约束，启动器可操控空间小** |
| 账户 | 微软账户 → 游戏档案 → 令牌注入参数 | 微软账户 → 应用商店/平台身份，登录态由系统/平台侧持有 |
| 多实例 | 天然支持，目录隔离即可 | 受限，取决于平台分发机制与沙箱 |
| 模组生态 | 加载器注入类路径 | 插件/附加包，注入点与沙箱限制完全不同 |
| 合规重点 | 不分发本体与资源，仅从官方源获取 | 分发受平台商店条款约束更强，可操控空间更小 |
| 打包与更新 | 可自由更新 | 易与平台自身的更新机制冲突 |

> **架构结论**：Java 版与基岩版在"账户→身份"这一段可以复用，在"元数据→依赖→启动"这一段几乎完全不可复用。因此**不要试图做一个统一的"版本解析 + 下载 + 启动"内核**；正确做法是统一"安装实例 + 后端适配器 + 能力声明"这层薄壳，把差异完全关进各自适配器内部。**是否值得为这点复用度投入，由 P11 预研报告回答。**

## 6. 合规、安全、版权与分发风险

### 6.1 红线

| 项 | 界定 |
|---|---|
| **永不实现** | 不伪造 Mojang 官方会话；不劫持官方验证接口；不实现破解登录；不逆向混淆代码以复制其逻辑；不分发游戏本体、客户端 jar、官方资源与库；不内置来源不明的整合包；不冒用官方品牌（命名、图标、文案不得暗示官方出品） |
| **离线账户** | 可作为合法身份来源实现，但必须明确告知用户"无法进入正版验证服务器"，且该告知在启动前不可被默认跳过 |
| **第三方验证** | 可作为可选身份来源实现，默认关闭，由用户显式启用，并说明其依赖第三方服务的条款与可用性风险；不用于伪造官方会话，不接触官方验证接口 |
| **第三方服务条款** | 使用任何第三方内容源或验证服务前，须核对其条款；条款不允许的场景不实现 |

### 6.2 风险登记表

| 风险 | 类型 | 影响 | 缓解措施 |
|---|---|---|---|
| **离线账户进正版服务器被拒** | 功能/预期管理 | 用户认为"启动器坏了" | 启动前预检判定；界面显式告知；错误信息区分"服务器要求正版验证"与"网络/版本不匹配" |
| **第三方验证服务断供** | 可用性/合规 | 该来源整体不可用 | 默认关闭；启用时展示依赖说明；与微软/离线来源完全解耦，断供不影响主链路；错误分类明确为"第三方服务不可用" |
| **authlib-injector 类兼容问题** | 技术 | 第三方来源无法启动或与其他加载器冲突 | 第三方来源自行声明所需额外 JVM 参数；参数注入集中在启动计划组装环节；与加载器参数合并顺序明确；版本升级导致不兼容时降级为"该来源暂不可用"而非崩溃 |
| **JRE 再分发许可** | 版权/合规 | 法律风险 | 仅选择许可允许再分发的构建；随附许可文本；运行时下载而非打包；建立运行时来源许可台账 |
| **镜像投毒** | 安全 | 注入恶意文件 | 校验基准恒定取自官方元数据；镜像仅作字节传输通道；校验失败即丢弃并回退官方源 |
| **镜像条款与断供** | 合规/可用性 | 功能下线 | 默认关闭、用户显式启用、来源可配置、UI 可见当前来源；一键回退官方源 |
| 使用条款变化 | 合规 | 功能被迫下线 | 只依赖公开元数据接口；不把任何单一来源写死；保留可切换来源能力 |
| 令牌泄露 | 安全 | 账户被盗 | 系统级凭据保护加密存储；不写日志；不落明文文件；登出即清除 |
| 日志泄露隐私 | 安全/合规 | 个人信息外泄 | 日志默认本地；诊断信息导出前脱敏（令牌、UUID、用户名、路径） |
| 捆绑第三方内容 | 版权 | 侵权 | 图标、字体、音效全部自制或使用明确许可的素材；建立素材来源台账 |
| 元数据格式漂移 | 技术 | 新版本无法启动 | 解析器前向兼容；未知字段忽略；契约测试覆盖多年代版本 |
| 路径与编码问题 | 技术 | 特定用户必然失败 | 中文/空格/超长路径专项测试；统一以原生路径处理 |
| 杀软误报 | 分发 | 无法安装 | 避免可疑的自我替换与自解压行为；代码签名评估 |
| 单文件自解压拖慢首启 | 性能 | 用户体验差 | 优先资源合并型方案；首启预算纳入 P7 验收 |
| 磁盘与网络不可用 | 可用性 | 启动失败 | 预检 + 明确提示 + 断点续传 |
| 过度设计 | 工程 | 交付延期 | MVP 只做 Java 原版；抽象只在出现第二个实现时引入 |

## 7. 技术栈推荐（不展开实现）

| 层面 | 推荐 | 理由 | 明确不推荐 |
|---|---|---|---|
| 平台/形态 | Windows 桌面，单文件绿色版，双击即用 | 与目标形态一致；分发成本最低 | Web 套壳、需要用户预装运行时的方案 |
| 语言/框架 | C# + WPF（本工程已定方向，框架版本沿用既有约定） | 原生、体积极小、冷启动快、系统集成好 | Electron/Tauri 类重壳；JVM 系桌面框架；Qt |
| 目标框架 | 沿用既有 net48 路线（除非确认需要新 API，否则不换） | 目标机自带、产物 1–3 MB、冷启动最优 | self-contained 新框架单文件（体积膨胀一个数量级） |
| 架构模式 | MVVM + 分层 + 端口适配器 | UI 与引擎解耦，可测试 | 逻辑写进窗口事件 |
| 单文件化 | 依赖合并方案（资源合并型优先） | 不落地临时目录，首启不额外耗时 | 运行时自解压方案 |
| 网络 | 平台自带 HTTP 栈 + 连接池 | 零额外依赖，够用 | 引入重型 HTTP 框架 |
| 序列化 | 平台自带 JSON 能力 + 手写映射 | 元数据结构稳定，手写映射最稳、无反射开销 | 反射式大而全 ORM/框架 |
| 压缩 | 平台自带压缩库 | 满足 jar/zip 解压 | 引入压缩库依赖 |
| 存储 | 本地文件 + 系统凭据保护（令牌） | 无数据库依赖，便携 | 嵌入式数据库（MVP 不需要） |
| 日志 | 自研轻量结构化日志（本地文件） | 控制体积与格式，便于诊断导出 | 重型日志框架 |
| 测试 | 领域层纯单元测试 + 元数据"黄金样本"回归 + 手动端到端清单 | 成本最低、覆盖最关键的解析逻辑 | 早期追求自动化 UI 测试 |
| 依赖策略 | **每引入一个第三方包都必须写明理由与体积代价** | 依赖越少，合并越简单、启动越快、风险越小 | 默认"先装了再说" |

## 8. 全局验收标准（Definition of Done）

| 类别 | 验收标准 |

| 版本覆盖 | 至少覆盖 1.7.10 / 1.12.2 / 1.16.5 / 最新正式版 四个代表性版本 |

## 9. 已确认决策记录

> 原第 9 节为待确认清单；本节已由用户确认并固化为决策记录。背景与影响说明保留，便于后续评审时理解取舍理由。

### 决策 1 · 身份来源

| 项 | 内容 |
|---|---|
| 决策 | 离线账户可实现，但必须明确告知用户"无法进入正版验证服务器"；第三方验证可作为可选实现，默认关闭，由用户显式启用并说明依赖第三方服务条款；绕过正版验证永不实现 |
| 红线改写 | 不伪造 Mojang 官方会话、不劫持官方验证接口、不实现破解登录；离线/第三方验证作为可选身份来源存在 |
| 背景 | 身份来源直接决定合规边界与 UI 文案；离线来源不依赖网络、实现成本低，且能让启动链路在认证接入前被完整验证 |
| 影响 | `IAuthProvider` 扩展为支持微软、离线、第三方三种实现，需能表达身份来源类型、是否在线验证、启动时注入什么、是否需要额外 JVM 参数；启动前预检需判断当前账户与目标服务器是否可能被拒绝；P5 阶段纳入离线，第三方落入 P10 |
| 落地阶段 | 微软 + 离线 → P5；第三方 → P10（默认关闭） |

### 决策 2 · 自动下载 Java

| 项 | 内容 |
|---|---|
| 决策 | 可设置；`IRuntimeProvider` 支持多实现（本机探测、手动指定、未来自动下载）；MVP 只做本机探测 + 手动指定；P10 增加自动下载，默认关闭，用户可开；只选许可允许再分发的 JRE 构建，附许可文本，运行时下载，不打包进主程序 |
| 背景 | 自动下载是提升"开箱可玩"的关键，但引入分发许可与体积风险；把许可约束写进契约，避免后续实现走偏 |
| 影响 | P3 验收标准明确"MVP 内不含自动下载行为但扩展点就位"；P10 增加许可台账与卸载能力要求；主程序体积预算不受运行时影响 |
| 落地阶段 | 探测 + 手动指定 → P3；自动下载 → P10（默认关闭） |

### 决策 3 · 镜像源

| 项 | 内容 |
|---|---|
| 决策 | 可设置；`IContentSource` 支持多实现（官方源、镜像源）；MVP 只官方源；P10 镜像作为可选，默认关闭，用户显式启用，来源可配置，用户知情 |
| 背景 | 镜像能显著改善部分地区下载体验，但带来投毒、条款与断供风险；必须从架构上隔离"传输通道"与"信任基准" |
| 影响 | P2 引入来源策略抽象并固化硬约束：校验基准恒定取自官方元数据，镜像不被采信为真源；P10 要求 UI 可见当前来源并支持一键回退 |
| 落地阶段 | 官方源 → P2；镜像 → P10（默认关闭） |

### 决策 4 · 体积与冷启动预算

| 项 | 内容 |
|---|---|
| 决策 | 按 C# + WPF + net48 的软预算执行：主程序体积 ≤ 5 MB（目标 1–3 MB）；冷启动到可交互 ≤ 800 ms（宽松上限 1.5 s）；空闲内存 ≤ 80 MB；首启不落地临时目录，首启与二次启动差异 ≤ 200 ms；作为软预算，P7 用实测数据再调，P0–P6 不为此牺牲架构 |
| 背景 | 目标形态是 PCL2 式的轻量单文件启动器，性能是产品力的一部分；但过早为体积优化会破坏分层与可维护性 |
| 影响 | P7 增加软预算表与测量条件、偏差归因要求；明确"架构正确性优先于预算"的冲突处理规则 |
| 落地阶段 | P7 实测校准；P0–P6 仅做约束记录 |

### 决策 5 · 第二阶段优先级

| 项 | 内容 |
|---|---|
| 决策 | 先打磨 MVP（P0–P7）；第二阶段优先 Java 深度功能：多实例 → Fabric/Forge 加载器；之后做基岩版可行性预研，只调研不写代码；预研结论决定是否真正接基岩版 |
| 背景 | Windows 基岩版是 UWP/MSIX 体系，启动器可操控空间小，与 Java 版复用度低；在没有充分论证前投入实现风险高 |
| 影响 | P8+ 拆分为 P8 多实例 → P9 加载器 → P10 可选能力 → P11 基岩版可行性预研（零代码）；第 5 节增补"分发与沙箱体系"维度作为预研理由的书面依据；P11 默认预期为"不接或仅做极有限封装"，需报告证实或推翻 |
| 落地阶段 | P8 → P9 → P10 → P11 |
