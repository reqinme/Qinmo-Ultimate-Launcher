### ⚠️ 一条改变降级路径设计的操作事实

**Mojang 的表单不提供申请编号，也没有查询进度的面板。**

这不是"信息缺失"，而是**这个流程的输出形态就是那样**。而它的后果很具体：

> **我们无法主动探测审批结果** —— 没有轮询目标、没有状态字段。
> 所以**唯一能知道它通过了的时刻，就是用户真的去尝试登录的那一刻。**

**于是 `identity.rs` 里 `Submitted` 状态的文案在 M0 收口时被改过：**

| | 文案 | 问题 |
|---|---|---|
| 第一版 | 「审批有外部等待期，你无需操作；**结果出来后会自动可用**」 | **那是一个我们做不到的承诺** —— 它会让用户**等一个不会来的通知** |
| 现在 | 「审批有外部等待期，你无需操作。**我方无法查询进度** —— 提交表单不提供编号与状态面板，所以只有在你实际尝试登录时，才能知道审批是否已经通过。」 | 诚实，且指出了真正的发现时机 |

有一条测试专门钉住它：`提交后的文案不许承诺我们做不到的事`（断言文案里必须含"无法查询"、**不许**含"会自动可用"、且要提到"登录"）。

## 4. `client_id` 落在哪 —— **配置，不是代码**

`docs/配置与设置规格.md` §7 明写 **"CSP 白名单（编译期常量，不是配置项）"**，
所以配置里有**两类东西**。判断一个值属于哪一类，判据是：

| 类别 | 判据 | 例子 |
|---|---|---|
| **编译期常量** | 改了它**必须改代码**（因为代码逻辑依赖它，如 CSP 策略） | CSP 白名单 |
| **配置项** | 改了它**只是换个值**，代码逻辑不变 | **`client_id`** · 主题 · 并发数 |

`client_id` 属于后者：**换一个 Azure 应用不影响任何一行逻辑**。
所以它进 `%APPDATA%\Qinmo\config.json` 的 `launcher` 段
（**微软登录是启动器级的**：它同时供 Java 与基岩两个产品，不属于任何单一产品）。

> **"不落在代码里"的真正含义**：`client_id` 本身是个公开字符串，
> 拷进二进制也无所谓；**关键是"改它不该需要重编译"** ——
> 因为方案的硬要求是"**审批中途通过 → 无需改动代码**"。
> 把"不进代码"理解成"保密"会得出错误结论（它根本不保密）。
