## 2. 共享启动管线

命令行与界面**必须走同一条链路**。两条各自实现的路径一定会漂移，
然后出现"命令行能启动、界面不能"这种最难查的问题。

`LaunchPipeline` 提供四个档位：

| 档位 | 到哪一步停下 |
|---|---|
| `PlanOnly` | 元数据 → Java → 下载计划 |
| `Install` | 再加下载 |
| `Prepare` | 再加启动计划组装与 natives 解压 |
| `Launch` | 整条链路，直到进程被拉起 |

`CliRunner` 与界面都只是它的薄封装。重构后 1.7.10 的骨架指纹仍是
`49331bc0b7d3`——**与重构前逐字节一致**，这是"重构没有改变行为"的直接证据。

### 进度必须同步转发

`Progress<T>` 会把回调**异步投递到线程池**。后果是下载进度在流程结束后才到达：
命令行里表现为顺序错乱，界面里表现为进度条不动然后突然跳完。
因此管线内部用同步转发，是否切线程由调用方决定。

## 3. 预检清单

| 标识 | 适用范围 | 严重度 | 含义 |
|---|---|---|---|
| `identity.capability` | **始终** | 警告 / 提示 | 身份来源的能力限制，**必须被确认后才能启动** |
| `java.available` | 始终 | 阻断 | 找不到满足版本要求的 Java |
| `client.installed` | 始终 | 提示 | 尚未就位，首次启动会先下载（**不是错误**） |
| `disk.space` | 始终 | 阻断 | 磁盘空间不足 |
| `server.address` | **仅当配置了目标** | 警告 | 目标不像一个服务器地址 |
| `server.compatibility` | **仅当配置了目标** | 警告 | 当前身份来源可能进不去该目标 |

### 最要紧的一条纪律：没配目标就什么都别说

启动器通常不知道用户要连哪个服务器。因此**服务器相关结论只在用户显式配置了目标时产生**。

一个凭空冒出来的服务器警告，比没有警告更糟——它会让用户开始怀疑一个根本不存在的问题。

这一点由测试直接断言"未配置目标时，`WhenTargetConfigured` 范围的条目数为 0"来守住，
空串与纯空白同样算未配置。

### 地址形状判断按字符集，不按"有没有空格"

一个中文串、一段带协议的 URL、一句粘贴错的说明文字，都该被认出来不是地址。
按"有没有空格"判断会把这些全部放过去。这个判断**只用来提醒，绝不用来拦人**。

### 磁盘不足要提前说，不是等下载到一半才报

预检按"预估体积 + 256 MB 余量"判断，在下载开始前就把话说清楚。

## 4. 诊断信息模板

"复制诊断信息"产出的是下面这份文本。它的唯一目标是：
**用户点一下就能把能定位问题的信息交出来，而且交出来的东西不泄露任何秘密。**

```
# Qinmo Ultimate Launcher 诊断报告
生成时间 / 启动器版本 / 操作系统 / 进程架构 / 数据目录方式

## 身份          来源、在线验证与否
## 版本与计划     版本 id、骨架指纹
## Java          选定运行时、选定路径、全部候选
## 启动前预检     每项的 [范围/严重度] 标识 标题 与明细
## 结果          错误码、人话提示、细节、过程记录
## 日志尾部      最近 80 行
## 复现步骤      1..5，让接手的人照着做一遍就能重现
```

**没有复现步骤的报告等于把排查成本丢给用户。**

## 5. 脱敏规则

| 内容 | 处理 |
|---|---|
| 已登记的访问令牌等秘密值 | → `<redacted>`（长度信息也不保留） |
| 数据根路径 | → `%DATA%` |
| 用户目录路径 | → `%USERPROFILE%` |
| UUID | → `<uuid>` |
| IPv4 地址 | → `<ip>` |

两个要点：

1. **报告的结构里根本没有令牌字段。** 秘密不是"被脱敏掉了"，而是**从来没有传入的机会**——
   这是比脱敏更强的保证。
2. **每一行都必须经过脱敏管道。** `DiagnosticReportBuilder` 里只有一个私有方法会往报告里写内容，
   它无条件调用脱敏。这不是一句约定，而是结构上只有这一个出口。

由测试覆盖：把秘密、路径、UUID、IP 分别塞进报告的各个字段，断言输出里一个都找不到。
