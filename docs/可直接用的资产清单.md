#### (a) `instance.cfg` 的 **`Override*` 双层覆盖模式**（`MinecraftInstance.cpp:82-135`）——**建议直接采纳**

**"是否覆盖"与"覆盖成什么"是两个独立事实**，重置只需关 `Override*`。
→ **比"有值就覆盖"清晰**。我们 §5.5 讲的"全局与实例配置层级合并"应采用这个模式。

#### (b) ⭐ **依赖冲突：MultiMC 用元数据声明，Prism 退化成代码硬编码**

| | MultiMC | Prism |
|---|---|---|
| 依赖/冲突来源 | **元数据声明** `m_cachedRequires` / `m_cachedConflicts`（`Component.h:94-95`） | **代码硬编码** `KNOWN_MODLOADERS` 映射表（Prism `Component.h:47-50,62,77`） |
| 加一个加载器 | **只需它自己的元数据声明** | **要改 C++ 映射表** |
| 额外能力 | **`suggests` 建议版本** + 自动清理 | 无 |

**schema**（`JsonFormat.h:42-68`、`OneSixVersionFormat.cpp:208-226`）：

```jsonc
{ "requires": [ {"uid":"net.minecraft","equals":"1.20.1","suggests":"1.20.2"} ],
  "conflicts": [ {"uid":"org.lwjgl3"} ],
  "mcVersion": "1.20.1",   // 简写 → 自动转 requires net.minecraft equals
  "volatile": true }
```

**⚠️ 两个上游真实缺陷，抄时必须避开**：

| 缺陷 | 位置 | 我们怎么做 |
|---|---|---|
| 字段名不一致：写入 `cachedVolatile`（`:94-97`）但读取找 `"volatile"`（`:117`）→ **该字段永远读不回来** | `PackProfile.cpp` | 读写用同一键名 |
| `RequireSet = std::set<Require>`，`operator<` **只比 uid**（`JsonFormat.h:48-51`）→ **同一 uid 的两个不同版本约束会被去重掉一个** | `JsonFormat.h` | 用 map/vec |

**合成算法**（`ComponentUpdateTask.cpp:290-381`）：同 uid 合并时
① `indexOfFirstDependee = min`（最早依赖者优先 → 决定顺序）
② `equals` 一方空取另一方、相同取值、**不同则冲突**（`:310` 标了 FIXME）
③ `suggests` 取**更大版本**（`:324-326`）。任一合并失败即整体失败（`:370`）。
**自动清理**（`:384-399`）：`dependencyOnly && volatile && 无人依赖` → 自动移除。

#### (c) 组件 UID 体系（跨启动器互通的既成标准）

**反向 DNS / Maven groupId 风格，全小写点分**：
`net.minecraft`（`PackProfile.cpp:508`、`OneSixVersionFormat.cpp:215`）· `net.minecraftforge`（`:559`）· **`net.fabricmc.fabric-loader`**（`InstanceImportTask.cpp:457`）·
`com.mumfrey.liteloader`（`:560`）· **`org.lwjgl` / `org.lwjgl3`（内建 patch，`:505-508`）**

→ **LWJGL 也是一等组件**，不藏在版本 JSON 里。
**`patches/<uid>.json` 的"文件名即 uid"约定**（`PackProfile.cpp:520` `info.completeBaseName()`）——很实用。

#### (d) `Validator` 流式校验模式（`net/ChecksumValidator.h`）

`init()` 重置 → `write(data)` **边下边算**（零额外读盘）→ `validate()` 比对。三个细节：
① **算法是参数**（整合包可能用 MD5）；② `setExpected()` 可后设；
③ **`MetaCacheSink` 自带 MD5** → **缓存失效与内容校验复用同一套哈希**。
**⚠️ 缺口**：`BaseEntity.cpp:88` 的 TODO 表明**元数据文件自身不校验**——而它是所有校验的信任根。**我们要补。**

### 2.14 ⭐ 与 Prism 的差异总表（**"元数据声明优于代码硬编码"**）

| 能力 | MultiMC | Prism | 我们取 |
|---|---|---|---|
| 依赖/冲突 | 元数据声明 | 代码硬编码 | **MultiMC** |
| `suggests` 建议版本 | 有（取更大） | 无 | **MultiMC** |
| 依赖自动清理 | `dependencyOnly + volatile` | 无 | **MultiMC** |
| 依赖顺序推导 | `indexOfFirstDependee` | 无 | **MultiMC** |
| 流式校验器 | 算法参数化 | 未确认 | **MultiMC** |
| 配置覆盖语义 | `Override*` 双层 | 未确认 | **MultiMC** |
| 组件栈 | 有（Prism 继承） | 有 + UI 模型一体化 | **Prism**（抽象更完整） |
