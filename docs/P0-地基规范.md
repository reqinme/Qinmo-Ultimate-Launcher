# P0 · 地基规范

> 依据：《Minecraft 启动器 · 架构规划与路线图（v1.2 正式版）》P0 阶段交付物。
> 本文件固化四件事：仓库与运行时目录布局、分层与命名空间约定、配置 Schema、错误码与日志字段字典。
> 变更规则：本文件是 P1 之后的共同契约。任何修改都必须同时更新受影响的下游实现，不允许"文档一套、代码一套"。

---

## 1. 架构决定：单程序集 + 命名空间分层

| 项 | 决定 | 理由 |
|---|---|---|
| 程序集数量 | **主程序 1 个程序集**（`QinmoUltimateLauncher.exe`），分层用命名空间表达 | 产品第一约束是"单文件、免安装、体积极小、首启不落地临时目录"。多程序集必须依赖合并（ILMerge / 装配件合并），而 WPF 的 BAML 资源在合并时脆弱，且带临时目录解压的方案直接违反首启约束。零依赖的程序集天然就是单文件 |
| 分层强制手段 | 命名空间约定 + 架构守卫测试 | 编译期无法跨程序集强制，因此用测试守住依赖方向（见 §2.3） |
| 测试工程 | 独立程序集 `Qul.Tests`，**不随产品分发** | 测试依赖不计入产品体积预算 |
| 实测依据 | Release 发布产物 **7,168 字节**，无任何第三方运行时依赖 | 见《P0 技术验证尖刺报告》S1 |

> 该决定不削弱文档第 4.1 节的分层要求：依赖方向仍然只允许指向内层，只是强制手段从"程序集引用"改为"命名空间约定 + 守卫测试"。

## 2. 目录规范

### 2.1 仓库布局

```
<repo root>/
  QinmoUltimateLauncher.slnx            解决方案
  Directory.Build.props          （预留）跨工程共享的构建属性
  .gitignore
  docs/                          规划与规范文档
  src/QinmoUltimateLauncher/            主程序（net48 / WPF / WinExe）
    App.xaml(.cs)                应用入口
    MainWindow.xaml(.cs)         （P6 起被主界面取代）
    Domain/                      领域层
    Application/                 应用层
    Infrastructure/              基础设施层
    Presentation/                表示层
    Properties/                  程序集级属性
  tests/Qul.Tests/    测试工程（net48）
  bin/ obj/ publish/             构建产物 —— 一律排除，不检索、不统计
```

**检索与统计纪律**：`bin/`、`obj/`、`publish/`、`*.log` 永远排除。启动器仓库的大部分体积来自生成物，不排除会让每次搜索都被灌满。

### 2.2 运行时目录布局（绿色版优先）

```
<exe 所在目录>/
  QinmoUltimateLauncher.exe             单文件主程序
  QinmoUltimateLauncher.exe.config      运行时配置（net48 必需）
  data/                          便携数据根
    config.json                  用户配置（见 §3）
    state/                       运行状态：缓存索引、已装内容记录
    logs/                        会话日志
      session-<yyyyMMdd-HHmmss>-<6位会话号>.log
    cache/
      meta/                      版本清单索引与版本详情 JSON
      libraries/                 库（按官方 groupId/artifactId 布局）
      objects/                   资源对象（按哈希前两位分目录）
    secrets/                     **仅存 DPAPI 密文**，绝不存明文
  game/                          默认游戏目录（.minecraft 布局）
```

| 规则 | 内容 |
|---|---|
| 便携优先 | 数据根默认取 `<exe 所在目录>/data` |
| 只读回退 | 若 exe 目录不可写（例如安装在受保护位置），回退到 `%APPDATA%\QinmoUltimateLauncher\data`，并在启动日志中记录实际生效路径 |
| 路径安全 | 所有用户可见路径必须支持中文、空格；超长路径按 S7 结论处理（见尖刺报告），不得假设系统已启用长路径 |
| 秘密隔离 | 令牌密文只放 `data/secrets/`；`config.json` 中**永不出现任何凭据字段** |

### 2.3 分层与命名空间约定

| 命名空间 | 层 | 职责 | 允许依赖 |
|---|---|---|---|
| `Qul.Domain` | 领域层 | 纯模型与规则：版本元数据模型、规则求值、启动计划、身份档案 | **无外部依赖** |
| `Qul.Application` | 应用层 | 用例编排：登录、安装、启动、取消、预检 | Domain + 端口接口 |
| `Qul.Infrastructure` | 基础设施层 | HTTP、文件系统、压缩、Java 探测、凭据存储、进程 | Domain 定义的端口 |
| `Qul.Presentation` | 表示层 | 视图与视图模型、状态展示、日志呈现 | Application |

**领域层禁令（由守卫测试强制）**：`Qul.Domain` 下的类型，其字段、属性、方法签名与基类型中不得出现下列命名空间：

- `System.Windows`、`System.Windows.Controls`、`System.Windows.Media`（WPF）
- `System.Net.Http`、`System.Net.Sockets`（网络）
- `System.IO`（文件系统）
- `System.Diagnostics.Process`（进程）

领域层允许 `System`、`System.Collections.Generic`、`System.Linq`、`System.Text`，以及纯数据契约。

**守卫测试**：`tests/Qul.Tests/Architecture/LayerDependencyTests.cs`。测试通过反射遍历领域层公开与私有成员的类型签名，命中禁令命名空间即失败。该测试随分层推进逐步收紧，P0 建立骨架，P1 起覆盖真实类型。

## 3. 配置 Schema（v1）

`data/config.json`。**只存用户意图，不存运行状态**；状态放 `data/state/`。

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `schemaVersion` | int | `1` | 配置结构版本；升级时按版本迁移 |
| `identity.source` | enum | `offline` | `offline` / `microsoft` / `thirdparty`。**默认离线**，符合"可选能力默认关闭"原则 |
| `identity.offlineUserName` | string? | `null` | 离线账户显示名；仅本地标识 |
| `identity.lastAccountKey` | string? | `null` | 上次使用账户的**非秘密**标识键（不是令牌、不是 UUID） |
| `java.mode` | enum | `auto` | `auto` / `manual` |
| `java.manualPath` | string? | `null` | 手动指定的 Java 可执行路径；仅 `manual` 时生效 |
| `memory.maxMb` | int? | `null` | 为空表示使用安全默认值，不由启动器猜测用户机器上限 |
| `launch.gameDirectory` | string? | `null` | 为空表示使用 `<data 根>/../game` |
| `launch.extraJvmArgs` | string[] | `[]` | 用户附加 JVM 参数 |
| `launch.serverQuickConnect` | string? | `null` | **可选**：用户显式配置的服务器地址。存在时才触发 P6 条件式服务器预检 |
| `launch.recentServers` | string[] | `[]` | 最近服务器；同样只用于条件式预检 |
| `network.proxyMode` | enum | `system` | `system` / `manual` / `direct` |
| `network.proxyAddress` | string? | `null` | 仅 `manual` 时生效 |
| `network.allowInvalidCertificate` | bool | **`false`（不可配置为 true）** | 保留字段用于显式表达"永不绕过证书校验"；不提供开启入口 |
| `contentSource.kind` | enum | `official` | MVP 只有 `official`；`mirror` 在 P10 引入且默认关闭 |
| `contentSource.mirrorBaseUrl` | string? | `null` | P10 字段，MVP 阶段必须为 `null` |
| `javaRuntime.autoDownload` | bool | **`false`** | P10 字段，默认关闭 |
| `diagnostics.logLevel` | enum | `info` | `error` / `warn` / `info` / `debug` |

**Schema 硬约束**

1. `config.json` 中**不得出现**：`accessToken`、`refreshToken`、`uuid`、任何完整绝对路径形式的用户目录以外的路径、任何密码类字段。
2. 配置损坏时必须降级：解析失败 → 重命名损坏文件为 `config.json.corrupt-<时间戳>` → 用默认值启动 → 记录 `QUL-CFG-0002`。**绝不因为配置损坏而拒绝启动。**
3. 未知字段必须忽略并保留原值（前向兼容）。
4. `schemaVersion` 高于程序支持的版本时，只读不写，并提示用户。

## 4. 错误码清单

格式：`QUL-<域>-<4 位序号>`。**每个错误码对应唯一的人话提示与唯一的处置建议**；同一码不得表达两种原因。

| 错误码 | 含义 | 用户可见提示要点 |
|---|---|---|
| `QUL-CFG-0001` | 配置读取失败（权限/IO） | 无法读取配置，已按默认值启动 |
| `QUL-CFG-0002` | 配置解析失败（损坏） | 配置已损坏，已备份并重置为默认 |
| `QUL-CFG-0003` | 配置版本高于程序支持 | 配置来自更新版本，已只读挂载 |
| `QUL-IO-0001` | 数据目录不可写 | 已回退到用户目录 |
| `QUL-IO-0002` | 磁盘空间不足 | 需释放空间，并给出所需量 |
| `QUL-IO-0003` | 路径过长 | 建议缩短游戏目录路径 |
| `QUL-NET-0001` | 网络不可达 | 检查网络连接 |
| `QUL-NET-0002` | 代理配置无效 | 代理不可用，已提示切换 |
| `QUL-NET-0003` | TLS 证书异常 | **明确提示证书校验未通过；绝不提供"忽略"选项** |
| `QUL-NET-0004` | 请求超时 | 已重试 N 次仍失败 |
| `QUL-NET-0005` | 远端返回非成功状态 | 携带状态码，不携带响应体中的敏感内容 |
| `QUL-META-0001` | 版本清单索引获取失败 | 无法获取版本列表 |
| `QUL-META-0002` | 版本详情缺失或结构非法 | 该版本元数据异常，已拒绝使用 |
| `QUL-META-0003` | 继承链断裂或存在环 | 版本继承异常 |
| `QUL-META-0004` | 未知字段（非致命） | 仅记日志，不提示用户 |
| `QUL-DL-0001` | 下载失败（可重试） | 正在重试（第 N 次） |
| `QUL-DL-0002` | 校验和不匹配 | 文件损坏，正在重新下载 |
| `QUL-DL-0003` | 校验基准缺失 | 元数据未提供哈希，已拒绝下载该文件 |
| `QUL-ZIP-0001` | 压缩包条目越界（zip slip / 路径穿越） | **整包拒绝，且不落盘**；提示该文件不可信 |
| `QUL-ZIP-0002` | 压缩包结构非法 | 文件损坏 |
| `QUL-JAVA-0001` | 未找到可用 Java | 给出安装或手动指定的指引 |
| `QUL-JAVA-0002` | Java 版本不满足该版本要求 | 说明需要的主版本与当前探测结果 |
| `QUL-JAVA-0003` | Java 可执行文件无效 | 手动路径无效 |
| `QUL-AUTH-0001` | 用户取消授权 | 已取消登录 |
| `QUL-AUTH-0002` | 令牌过期且刷新失败 | 需重新登录 |
| `QUL-AUTH-0003` | 账户无该游戏所有权 | 该账户不拥有游戏 |
| `QUL-AUTH-0004` | 第三方服务不可用 | 第三方验证服务不可用，不影响其他身份来源 |
| `QUL-AUTH-0005` | OAuth 前置条件未满足 | 微软正版登录当前不可用（不进入完成态） |
| `QUL-PLAN-0001` | 启动计划存在未替换占位符 | 内部错误，已阻止启动 |
| `QUL-PLAN-0002` | 启动计划骨架不一致 | 内部一致性校验失败 |
| `QUL-PROC-0001` | 进程启动失败 | 无法启动游戏进程 |
| `QUL-PROC-0002` | 游戏异常退出（非零码） | 携带退出码与日志尾部路径 |
| `QUL-PROC-0003` | 启动器退出时游戏仍在运行 | 询问是否一并结束 |
| `QUL-UPD-0001` | 更新失败（P7） | 已回退到旧版本 |

## 5. 日志字段字典

### 5.1 记录格式

结构化行式日志，每行一条记录，字段 `键=值`，`值` 需转义换行与分隔符。会话首行写入环境快照。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ts` | ISO8601 带时区偏移 | 是 | 记录时间 |
| `level` | `error`/`warn`/`info`/`debug` | 是 | 日志级别 |
| `session` | 6 位会话号 | 是 | 同一次启动器运行内一致；对应日志文件名 |
| `phase` | 见 §5.2 | 是 | 所处阶段 |
| `code` | 错误码 | 否 | 仅错误与警告携带 |
| `msg` | 文本 | 是 | 人读消息（**英文短句，不含用户数据**） |
| `detail` | 文本 | 否 | 附加信息，**必须先脱敏** |
| `elapsedMs` | 整数 | 否 | 该阶段或该次操作耗时，用于 S2 类性能回归 |

### 5.2 `phase` 取值

`boot`、`config`、`meta`、`download`、`verify`、`extract`、`java`、`auth`、`plan`、`process`、`ui`、`update`。

### 5.3 脱敏字段清单（强制）

下列内容**永不进入日志、永不出现在诊断导出中**，出现即视为缺陷：

| 类别 | 字段 |
|---|---|
| 凭据 | `accessToken`、`refreshToken`、任何授权码、任何 DPAPI 密文原文 |
| 身份 | 正版与离线 `uuid`、`userName` |
| 路径 | 完整绝对路径中的用户目录段（保留结构，替换用户名段） |
| 网络 | IP 地址、`serverAddress`、`serverQuickConnect`、`recentServers` 条目 |

**实现约定**：日志与诊断导出共用同一脱敏管道。禁止任何调用点绕过该管道直接写文件。

### 5.4 日志生命周期

| 规则 | 内容 |
|---|---|
| 落盘位置 | `data/logs/`，本地，不上传 |
| 轮转 | 保留最近 20 个会话文件，超出按时间删除最旧 |
| 诊断导出 | 导出前再过一遍脱敏管道；导出物中不得出现 §5.3 任一字段的真实值 |
| 崩溃场景 | 未捕获异常必须写入一条 `level=error` 且带错误码的记录，再进入统一异常出口 |
