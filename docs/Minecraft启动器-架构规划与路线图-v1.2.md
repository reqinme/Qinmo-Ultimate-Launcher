## 0. 设计原则

| 原则 | 含义 | 反面案例（要避免的） |
|---|---|---|
| 启动器只是"编排器" | 只做解析、获取、组装、拉起，不实现游戏逻辑 | 自己写资源加载、自己改 jar |
| 一切外部输入都不可信 | 版本 JSON、远端清单、下载内容全当脏数据 | 直接反序列化就信、不校验哈希 |
| 界面与引擎解耦 | UI 挂了不影响命令行启动；引擎可被 CLI/测试直接调用 | 逻辑写在 XAML 事件处理里 |
| 一个版本 = 一份不可变"启动计划" | 先算出完整计划，再执行；可预演、可导出、可复现 | 边下边拼参数，失败无法复现 |

> **v1.2 补充说明（不改变上述四条原则）**："启动计划"的"可复现"指**可复现骨架**逐字节一致，秘密字段以引用形式存在、不参与比对（详见 P4 与决策 7）。

## 1. MVP 范围与推荐实现顺序

### 1.1 MVP 边界（明确"做"与"不做"）

| 归类 | MVP 内 | MVP 外（延后至 P8+） |
|---|---|---|
| 版本 | 官方 Release 正式版，单一安装实例 | 快照、旧版 Alpha/Beta、多实例并存（P8） |
| 身份来源 | **离线账户（P4.0 前置最小实现，强制告知"无法进入正版验证服务器"）**；**微软正版账户（P5）** | 第三方验证（P10，可选、默认关闭）；多账户切换 |
| 内容 | 纯原版，无 mod / 无资源包 | Fabric / Forge / NeoForge / Quilt、整合包（P9） |
| Java | 本机 Java 探测 + 用户手动指定路径（P4 前置） | 自动下载运行时（P10，可选、默认关闭） |
| 内容来源 | 仅官方源 | 镜像源（P10，可选、默认关闭、用户显式启用） |
| 运行 | 组装参数、拉起进程、回收退出码与日志 | 性能调优、内存自动推荐、崩溃自动归因 |
| 安全基线 | **令牌系统凭据保护加密存储；解压路径穿越防护；日志与诊断导出脱敏；启动计划秘密与骨架分离** | 更细粒度的权限模型与审计 |
| 界面 | 一个页面：选版本 → 选身份来源 → 启动 + 日志窗 | 皮肤、新闻、主题、多语言 |
| 分发 | 单文件绿色版，本地运行 | 自动更新、统计遥测、崩溃上报（更新策略选型见 P7.0） |

> **MVP 成功定义一句话**：一个玩家，双击一个 exe，选择身份来源并登录（微软正版或离线），点一次启动，能进到游戏主菜单；若使用离线账户，界面必须明确提示其无法进入正版验证服务器。

### 1.2 推荐实现顺序（每步都可独立验证，不要跳步）

> **v1.2 顺序修订**：采用 **方案 A** —— 把"离线身份最小实现"提前为 **P4 的前置子任务（P4.0）**，使 P4 的验收不再依赖 P5；P5 专注微软正版与完整身份能力，且不再阻塞 P4。

| 序 | 里程碑 | 为什么排这个位置 | 该步结束时的可验证状态 |
|---|---|---|---|
| 1 | P0 地基与规范 + **技术可行性尖刺** | 后面所有模块都依赖它；关键假设必须在写产品代码前验证 | 目录/日志/错误码就位；尖刺报告成文并给出风险结论与处置建议 |
| 2 | P1 版本清单获取与解析 | 启动链路的"数据源"，纯逻辑、最易测 | 能列出所有正式版、能取到指定版本的完整 JSON |
| 3 | P2 下载器（并发/校验/续传/缓存/解压安全） | 全链路最大的失败源，必须最先做扎实 | 断网续传、坏文件自动重下、重复请求命中缓存、恶意压缩包被拒绝 |
| 4 | **P4.0 离线身份最小实现** + P3 Java 运行时探测与选择 | 离线身份不依赖网络，必须早于启动链路就位；Java 探测可离线验证 | 离线身份可产出身份档案并带强制告知；Java 选择正确、可手动指定 |
| 5 | P4 主体：启动计划骨架组装 + 进程管理 | 前四步的汇聚点；此时离线身份已在手，可直接跑通全链路 | 能拉起原版客户端并看到游戏窗口；骨架可逐字节比对、导出脱敏 |
| 6 | P5 微软正版身份与完整身份能力 | 前置条件（OAuth 应用注册与条款）确认后方可进入完成态；不阻塞 P4 验收 | 微软正版可登录并进入游戏；令牌加密存储与静默刷新就位 |
| 7 | P6 UI 串联与错误诊断 | 界面前置于此，是为了不把时间浪费在改 UI 上 | 全流程一次点通；身份来源能力限制被强制告知；失败有人话级提示 |
| 8 | **P7.0 更新策略选型** → P7 发布工程（单文件、体积、冷启动） | 更新机制与杀软误报、回退强相关，选型不得晚于 P7 开始 | 更新方案选型成文；单 exe 可分发，五项软预算完成实测 |

> **关键顺序纪律**：P4 的链路验证统一使用 **离线账户** 作为身份提供方——它本身就是 MVP 内合法可交付的身份来源之一，不需要临时桩代码，也天然规避了认证环节对网络与浏览器环境的依赖。**P5 的任何风险或延期都不得阻塞 P4 的验收。**

## 2. 分阶段路线图（目标 / 任务 / 交付物 / 验收）

### P0 地基与规范（含技术可行性尖刺）

| 项 | 内容 |
|---|---|
| 目标 | 建立不可动摇的目录、配置、日志、异常约定；**在写产品代码之前验证关键技术假设** |
| 关键任务 | 分层骨架（UI/应用/领域/基础设施）；`.minecraft` 布局兼容；配置读写与迁移；结构化日志（含启动会话 ID）；统一错误码；**执行技术验证尖刺（Spike）** |
| 交付物 | 目录规范文档；配置 Schema；错误码清单；日志字段字典；**技术验证尖刺报告（含风险结论与处置建议）** |
| 验收标准 | 全新机器首次运行能自动建目录；配置损坏时能降级而非崩溃；任一失败都有唯一错误码 + 人话提示；**尖刺报告的验证项全部有明确结论；尖刺过程不产生任何产品代码；结论已被登记并作为 P7 软预算与依赖选择的正式输入** |

#### P0 · 技术验证尖刺（Spike）范围

> 尖刺的定义：只验证关键假设、只产出结论，**不写产品代码**。尖刺结论影响 P7 的软预算数值与依赖选择，但**不要求 P0–P6 为性能牺牲架构**（见 P7 预算纪律）。

| # | 尖刺项 | 要回答的问题 | 结论形式 |
|---|---|---|---|
| S1 | 单文件资源合并 | 依赖合并为单文件后，首启是否落地临时目录？是否影响冷启动与体积？ | 合并方案可行性结论 + 推荐合并方式 |
| S2 | 冷启动基线 | 目标形态下的空壳冷启动是否接近 ≤ 800 ms 软预算？差距来自何处？ | 基线数值 + 差距归因 |
| S3 | 手写 JSON 映射 | 面对四个年代版本的元数据结构，手写映射是否足够稳定与可维护？ | 稳定性结论 + 是否需要备用方案 |
| S4 | 微软 OAuth 可行性 | 回调 URI 与设备码两条路径在本工程形态下是否均可落地？应用注册前置条件是否可满足？ | 可行路径结论 + 前置条件清单 |
| S5 | Java 探测与版本解析 | 常见安装形态、PATH 方式、旧式与新式版本号是否都能正确解析？架构识别是否可靠？ | 覆盖清单 + 已知盲区 |
| S6 | 凭据保护可用性 | DPAPI 凭据保护在当前用户配置与漫游/多用户场景下是否可用？ | 可用性结论 + 降级策略 |
| S7 | 中文/空格/超长路径 | 关键路径（游戏目录、缓存、natives、Java 路径）在中文、空格、超长场景下是否可正常处理？ | 通过/不通过 + 处置建议 |
| S8 | 杀软误报初判 | 目标形态（单文件、进程拉起、依赖合并）是否触发常见误报？ | 初判结论 + 缓解方向 |

| 项 | 内容 |
|---|---|
| 尖刺验收 | 八项验证全部有书面结论；每项给出"可行 / 有条件可行 / 不可行"判定；不可行或有条件可行项给出处置建议与影响范围 |
| 尖刺边界 | 不产生产品代码、不产生可交付功能；报告只描述验证方式、观察结果与结论 |
| 结果去向 | 汇入 P7 软预算与依赖选择；涉及 OAuth 的结论汇入 P5 前置条件门禁；涉及路径与凭据的结论汇入 P2/P4/P5 安全基线 |

### P1 版本元数据

| 项 | 内容 |
|---|---|
| 目标 | 完整、正确地理解"一个版本是什么" |
| 关键任务 | 版本清单索引解析（含 latest/release/snapshot）；版本 JSON 解析；`inheritsFrom` 继承合并；`rules` 规则求值（系统/架构/特性）；新旧两种参数写法兼容；`javaVersion` 与 `downloads` 结构解析 |
| 交付物 | 版本元数据模型说明；继承与规则求值规则书；兼容性测试清单（跨多个年代版本） |
| 验收标准 | 任取 1.7.10 / 1.12.2 / 1.16.5 / 最新正式版四个版本，解析出的库列表、主类、参数与官方启动器一致；遇到未知字段不崩溃（前向兼容） |

### P2 下载与缓存

| 项 | 内容 |
|---|---|
| 目标 | 任何资源都能"最终正确落盘"，且不重复劳动；来源可替换而不影响正确性；**解压与网络异常处理安全可控** |
| 关键任务 | 库/客户端 jar/资源索引/资源对象四类下载通道；**SHA-1 校验基准恒定取自官方元数据**；并发与限速；断点续传；失败重试与退避；缓存目录与垃圾回收；磁盘空间预检；**引入"来源策略"抽象**（`IContentSource` 多实现），MVP 仅注册官方源；**通用解压安全规范（zip slip 与路径穿越防护：拒绝绝对路径、拒绝 `..` 越界、拒绝符号链接逃逸、解压目标限定在受控根目录内、越界条目即整包拒绝且不落盘）**；**代理设置支持（跟随系统 / 手动指定 / 直连）与 HTTPS 证书异常分类处理（证书异常给出明确分类提示，绝不静默忽略或降级绕过）** |
| 交付物 | 下载任务模型；缓存布局文档；重试与校验策略说明；**来源策略说明（含"校验基准永不来自镜像"这条硬约束）**；**解压安全规范**；**网络环境处理说明（代理与证书异常分类）** |
| 验收标准 | 拔网线中途恢复后能续传完成；故意损坏一个已缓存文件能被检出并重下；重复启动同一版本不产生冗余网络请求；单文件失败不影响整体可重试；**MVP 阶段配置中不存在镜像开关，代码路径中不存在"信任远端提供哈希"的可能**；**构造含路径穿越或绝对路径条目的压缩包时被拒绝，且受控根目录外无任何文件落地**；**代理配置可生效；证书异常被明确分类提示，而非静默绕过** |

### P3 Java 运行时

| 项 | 内容 |
|---|---|
| 目标 | 找得到、选得对、说得清；为未来的运行时来源扩展留好接口边界 |
| 关键任务 | 常见安装位置与 PATH 探测；版本号解析（含旧式 1.8.0_x 与新版 17/21）；按 `javaVersion.majorVersion` 匹配；架构匹配（x64/arm64）；用户手动指定覆盖；不可用时的明确指引；**`IRuntimeProvider` 按多实现设计并声明能力（是否可下载、是否需许可告知）** |
| 交付物 | Java 探测规则表；候选排序策略；不可用时的提示文案；**运行时来源能力矩阵（本机探测 / 手动指定 / 未来自动下载）** |
| 验收标准 | 本机存在多个 Java 时自动选中满足该版本要求的最新可用者；用户手动指定的路径优先生效且可校验有效性；无可用 Java 时不报堆栈而是给出可执行指引；**MVP 内不包含任何自动下载行为，接口层面的扩展点已就位** |

| 项 | 内容 |
|---|---|
| 目标 | 把元数据 + 身份 + Java + 配置，变成一份可复现、可脱敏导出的启动计划，并可靠拉起进程 |
| 关键任务 | **P4.0 离线身份最小实现（前置）**；启动计划骨架组装；**计划秘密与骨架分离**；natives 分类器筛选与解压（含解压安全规范）；类路径顺序；JVM 参数与游戏参数分组合并；占位符替换；工作目录设定；进程启动、标准输出捕获、退出码处理；子进程生命周期与"启动器关闭后游戏是否存活"策略；**日志脱敏** |

#### P4.0 离线身份最小实现（P4 前置子任务）

| 项 | 内容 |
|---|---|
| 目标 | 在不依赖网络与任何外部认证服务的前提下，提供一份合法的本地身份，使 P4 验收可独立完成 |

| 离线 UUID 规范 | **仅作本地身份标识使用；不得冒充官方 UUID；不得伪造官方会话；不得用于任何形式的正版验证绕过；生成规则须在文档中写明并保证本地唯一、与官方标识可区分** |
| 交付物 | 离线身份生成与标识规则说明；强制告知的触发条件与文案要求 |
| 验收标准 | 离线身份可在无网络环境下产出身份档案；**必须在启动前出现"无法进入正版验证服务器"的显式告知，且不可被默认跳过**；生成过程中不产生任何伪造官方会话的行为 |

#### P4 启动计划模型（LaunchPlan · v1.2 重构）

> 原"整份计划逐字节一致"不可实现：计划包含访问令牌、UUID、用户名、实际路径、Java 路径、时间戳等易变或敏感字段。**v1.2 起，启动计划拆为两个平面。**

| 平面 | 内容 | 是否参与逐字节比对 | 导出处理 |
|---|---|---|---|
| **A. 可复现骨架** | 版本 ID、Java 主版本要求、类路径顺序（逻辑项）、natives 目录（逻辑标识）、JVM 参数模板、游戏参数模板、工作目录（逻辑标识）、环境变量键、身份来源类型、注入项键 | **是** | 可直接导出（不含任何秘密） |
| **B. 运行时秘密引用** | 令牌句柄、令牌存储引用、敏感身份字段（访问令牌、离线/正版 UUID、用户名）、解析后的实际绝对路径（Java、游戏目录、natives 目录）、时间戳与环境瞬时值 | **否** | 一律以占位符呈现，绝不输出真实值 |

| 项 | 内容 |
|---|---|
| 分离规则 | 骨架不含任何秘密或瞬时值；秘密以"句柄/引用"形式在计划中占位，**实际值仅在启动瞬间解析**；相同输入下骨架逐字节一致 |
| 比对规则 | 回归与一致性测试**只针对骨架**；秘密引用不参与任何逐字节比较 |
| 导出规则 | 人类可读导出必须脱敏：秘密字段以固定占位符呈现；路径类信息按"可诊断但可脱敏"策略处理 |
| 交付物 | 启动计划模型说明（含骨架/秘密两平面字段表）；参数组装规则说明；退出码含义表；**脱敏导出规则** |
| 验收标准 | 同一输入两次生成的**骨架**逐字节一致；**任何导出产物中不出现访问令牌、UUID、用户名等秘密字段的真实值**；natives 与 jar 解压拒绝路径穿越条目；游戏退出后启动器正确回收资源并保留完整日志（日志已脱敏） |

## 3. Java 版启动链路（七个环节的要点与陷阱）

| 环节 | 必须做对的事 | 常见陷阱 |
|---|---|---|
| ① 账户认证 | 走官方授权流程拿到游戏档案；**微软正版以 P5 前置条件（应用注册、client_id 与权限范围、回调 URI 或设备码、第三方启动器条款）确认为开工门槛**；令牌使用系统凭据保护加密存储；自动刷新；明确区分"未登录/无所有权/令牌失效/条款限制"；**离线来源由 P4.0 提供最小实现，其 UUID 仅作本地标识、不冒充官方 UUID**；**每次启动前强制告知身份来源的能力限制** | 明文存令牌；把刷新失败当登录失败；在 UI 线程做网络请求；把离线身份当作可进入正版验证服务器；在前置条件未确认时把微软登录标为完成 |
| ② 版本清单 | 先取索引再取版本详情；索引有缓存有效期；版本详情要落盘缓存但可强制刷新 | 每次启动都全量拉索引；把索引当版本详情用 |
| ③ 依赖下载 | 库按 `rules` 过滤后再下；注意 `natives` 分类器；客户端 jar 是独立下载项；全部校验 SHA-1；失败可重试可续传；**校验基准恒定取自官方元数据**；**代理与证书异常分类处理，绝不静默绕过证书错误** | 忽略规则求值导致下了 Linux 库；跳过校验；路径含空格/中文未处理；信任镜像提供的哈希；静默忽略证书异常 |
| ④ 资源索引 | 资源索引与资源对象是两层；索引为映射表，对象按哈希前两位分目录；新版索引可能不含虚拟目录映射，需自行处理映射缺失场景 | 把索引直接当文件列表；忽略映射结构差异导致旧版本资源错位 |
| ⑤ natives 解压 | 按平台分类器挑选 natives 包；解压到独立目录并排除 META-INF；把该目录加入类路径；每次启动前清理或按版本隔离；**强制执行解压安全规范（zip slip 与路径穿越防护，越界条目整包拒绝且不落盘）** | 直接把 natives 当普通库加进类路径；混用不同版本 natives 导致本地库冲突；不清理残留导致诡异崩溃；解压越界条目写入受控目录之外 |
| ⑥ JVM/游戏参数 | 严格按版本 `javaVersion` 选 Java；JVM 参数（内存、编码、本地库路径）与游戏参数（用户名、UUID、令牌、版本、资源目录、资产索引 ID）分组管理；占位符替换必须严格匹配官方约定；处理新式 `arguments` 与旧式 `minecraftArguments`；**启动计划按 A 可复现骨架 / B 运行时秘密引用分离，秘密仅在启动瞬间解析**；**身份来源差异只体现为"身份来源类型 + 注入项键"的不同**；**不假设启动器知道目标服务器** | 参数里出现未替换占位符；内存设置超出机器物理内存；缺少资源索引 ID 导致游戏内模型/贴图异常；为第三方来源硬编码注入逻辑而非走提供方契约；把秘密值写进可导出的骨架 |
| ⑦ 进程管理 | 独立工作目录；捕获 stdout/stderr 落盘；区分"启动器退出"与"游戏退出"；退出码映射为可读结论；异常退出保留上下文；**日志按脱敏清单处理（令牌/UUID/用户名/路径/IP/服务器地址）** | 用管道缓冲导致日志丢失；父进程结束时误杀游戏；不区分崩溃与正常退出；日志中残留令牌或个人路径 |

> **链路设计的核心产物**：**LaunchPlan（v1.2 双平面）**——A 可复现骨架（版本 ID、Java 主版本要求、类路径顺序、natives 目录逻辑标识、JVM 参数模板、游戏参数模板、工作目录逻辑标识、环境变量键、身份来源类型、注入项键）与 B 运行时秘密引用（令牌句柄、令牌存储引用、敏感身份字段、解析后的实际绝对路径、时间戳等瞬时值）。它是排障、复现、对比、"只预演不启动"能力的唯一支点；**逐字节一致性只针对骨架，导出必须脱敏**。

## 4. 可扩展架构建议

### 4.1 分层与依赖方向

| 层 | 职责 | 允许依赖 |
|---|---|---|
| 表示层 | 交互、状态展示、日志呈现 | 应用层 |
| 应用层 | 用例编排：登录、安装、启动、取消、预检 | 领域层 + 抽象端口 |
| 领域层 | 纯模型与规则：版本、规则求值、启动计划、身份档案 | 无外部依赖（可纯单元测试） |
| 基础设施层 | HTTP、文件系统、压缩、Java 探测、凭据存储、进程 | 领域层定义的端口 |

依赖永远指向内层。**领域层不允许出现 HTTP 客户端、文件路径、命令行的字样。**

### 4.2 核心抽象

| 抽象 | 解决的问题 | 未来受益场景 |
|---|---|---|
| `IGameBackend`（游戏后端适配器） | "启动一个游戏"的统一契约：预检、安装/准备、启动计划、进程监控 | Java 版、基岩版（若 P11 结论为接）、其他游戏各实现一个 |
| `IAuthProvider`（身份提供方） | 登录、刷新、登出、档案获取、能力声明 | 微软正版、离线、第三方验证 |
| `IContentSource`（内容源） | 版本清单、库、资源、附加内容的统一获取与元数据 | 官方源、镜像源、未来内容平台 |
| `IRuntimeProvider`（运行时提供方） | 运行时探测、选择、能力声明（未来含获取） | 本机探测、手动指定、自动下载 |
| `IInstallation`（安装实例） | 一次"可启动的配置"：版本 + 加载器 + Java + 内存 + 目录 | 多实例、整合包、多后端并存 |

#### `IAuthProvider` 扩展契约

| 契约要素 | 说明 |
|---|---|
| 身份来源类型 | 微软正版 / 离线账户 / 第三方验证（枚举化，UI 与预检据此决策） |
| 是否在线验证 | 该来源是否需要联网校验；离线为否 |
| 启动时注入什么 | **以"注入项键 + 值引用"表达**：用户名、UUID、令牌、用户类型标记、来源标识；**秘密值以引用形式存在，不进入可复现骨架** |
| 是否需要额外 JVM 参数 | 第三方来源可能要求注入代理类参数；由提供方自行声明，作为骨架中的参数模板项 |
| 能力声明 | 能否进入正版验证服务器、能否刷新、能否撤销、是否需加密存储 |
| 能力告知义务 | **提供方必须能输出面向用户的能力限制描述**，供 UI 在启动前强制展示 |
| 预检能力 | 在**用户已提供目标服务器**时，能否判断"当前账户 + 该目标"是否可能被拒绝；无目标时不得推断 |
| 令牌生命周期与安全 | 过期与刷新策略；**令牌必须以系统凭据保护（DPAPI）加密存储**；明文不落盘、不进日志；登出与撤销语义 |
| 本地标识规范 | 离线来源的 UUID 仅作本地身份标识；**不冒充官方 UUID、不伪造官方会话** |

**身份来源能力对照（落地阶段与默认状态）**

| 来源 | 落地阶段 | 默认状态 | 在线验证 | 可进入正版验证服务器 | 额外 JVM 参数 | 合规要点 |
|---|---|---|---|---|---|---|
| 离线账户 | MVP（**P4.0，P4 前置**） | 可用，**强制告知限制** | 否 | **否** | 否 | 不伪造官方会话；UUID 仅本地标识；UI 强制告知无法进入正版验证服务器 |
| 微软正版 | MVP（P5，**含前置条件门禁**） | 可用 | 是 | 是 | 否 | 走官方授权流程，令牌以 DPAPI 加密存储；前置条件未满足不得进入完成态 |
| 第三方验证 | P10 | **关闭** | 视服务而定 | 视服务条款而定，不保证 | 可能需要 | 默认关闭、显式启用、展示第三方条款；不接触官方验证接口 |

#### `IRuntimeProvider` 扩展契约

| 契约要素 | 说明 |
|---|---|
| 来源类型 | 本机探测 / 手动指定 / 自动下载 |
| 能力声明 | 是否可获取、是否需要许可告知、是否可卸载 |
| 许可合规标记 | 只有许可允许再分发的构建才可被"可获取"实现接受 |
| 选择策略 | 按版本要求的 Java 主版本 + 架构匹配 + 用户偏好排序 |
| 失效与回退 | 探测失败或下载失败时回退到手动指定或明确指引 |

**运行时来源实现矩阵**

| 实现 | 阶段 | 默认 | 说明 | 许可约束 |
|---|---|---|---|---|
| 本机探测 | MVP（P3） | 启用 | 扫描常见位置与 PATH，解析版本与架构 | 不涉及分发 |
| 手动指定 | MVP（P3） | 启用 | 用户指定路径，优先于自动选择 | 不涉及分发 |
| 自动下载 | P10 | **关闭** | 运行时按需下载到用户数据目录 | **只选许可允许再分发的 JRE 构建；附许可文本；绝不打包进主程序** |

#### `IContentSource` 扩展契约

| 契约要素 | 说明 |
|---|---|
| 来源类型 | 官方源 / 镜像源 |
| 能力范围 | 版本清单、版本详情、库、客户端、资源索引、资源对象 |
| 信任边界 | **清单与哈希的信任基准只能来自官方元数据；镜像仅是字节传输通道** |
| 用户可见性 | 当前生效来源必须在 UI 中可见 |
| 回退策略 | 可一键切回官方源；镜像失败不阻断官方源路径 |

**内容来源实现矩阵**

| 实现 | 阶段 | 默认 | 说明 | 风险 |
|---|---|---|---|---|
| 官方源 | MVP（P2） | 启用且唯一 | 存在性、正确性、许可最干净 | 速度受网络环境影响 |
| 镜像源 | P10 | **关闭** | 用户显式启用、来源可配置 | 投毒风险、条款风险、断供风险（详见 6.2） |

### 4.3 支撑性设计

| 设计 | 说明 |
|---|---|
| 能力声明而非能力假设 | 每个后端声明自己支持什么（是否支持 mod、是否支持多实例、是否支持离线、是否有资源索引）。UI 按能力渲染，而不是 `if (是Java版)` |
| 事件/进度总线 | 下载、校验、解压、启动各阶段统一上报进度与取消，UI 只订阅 |
| 一切耗时操作可取消 | 取消语义从 MVP 起就贯穿，后补成本极高 |
| 配置与状态分离 | 配置（用户意图）与状态（缓存、已装内容）分开存储，便于迁移与重置 |
| 契约测试 | 对每个后端实现跑同一套验收夹具（预检→准备→启动→回收） |
| 明确的"不做"边界 | 认证、版权素材、游戏逻辑一律不自己实现，只编排 |

### 4.4 非 MC 功能的预留方式

不要为"未来未知功能"提前造框架，只做两件事：**（1）** 应用层用"任务/用例"组织，新功能是一个新用例而非新窗口逻辑；**（2）** 主界面用"功能区/入口"注册表驱动，而非硬编码标签页。这两点足够，其余等真需求出现再抽象。

## 5. 基岩版与 Java 版启动差异

| 维度 | Java 版 | 基岩版（Windows） |
|---|---|---|
| 可执行形态 | JVM 进程 + jar/类路径 | 原生可执行程序（无 JVM） |
| 运行时依赖 | 需要匹配的 Java 运行时 | 通常依赖系统运行时组件，随包分发 |
| 版本与元数据来源 | 公开版本清单 + 版本 JSON | 无等价的公开启动清单，元数据来源完全不同 |
| 依赖模型 | 库 + natives + 资源索引，逐项下载校验 | 无"库/资源索引"概念，通常是整体包或应用包 |
| 启动方式 | 组装命令行参数拉起 | 启动应用/包，可能涉及应用容器与注册状态 |
| **分发与沙箱体系** | **绿色版目录，启动器可完全掌控文件与进程** | **UWP/MSIX 体系，受应用容器与平台沙箱约束，启动器可操控空间小** |
| 账户 | 微软账户 → 游戏档案 → 令牌注入参数 | 微软账户 → 应用商店/平台身份，登录态由系统/平台侧持有 |
| 多实例 | 天然支持，目录隔离即可 | 受限，取决于平台分发机制与沙箱 |
| 模组生态 | 加载器注入类路径 | 插件/附加包，注入点与沙箱限制完全不同 |
| 合规重点 | 不分发本体与资源，仅从官方源获取 | 分发受平台商店条款约束更强，可操控空间更小 |
| 打包与更新 | 可自由更新 | 易与平台自身的更新机制冲突 |

> **架构结论**：Java 版与基岩版在"账户→身份"这一段可以复用，在"元数据→依赖→启动"这一段几乎完全不可复用。因此**不要试图做一个统一的"版本解析 + 下载 + 启动"内核**；正确做法是统一"安装实例 + 后端适配器 + 能力声明"这层薄壳，把差异完全关进各自适配器内部。**是否值得为这点复用度投入，由 P11 预研报告回答。**

## 6. 合规、安全、版权与分发风险

### 6.1 红线

| 项 | 界定 |
|---|---|
| **永不实现** | 不伪造 Mojang 官方会话；不劫持官方验证接口；不实现破解登录；不逆向混淆代码以复制其逻辑；不分发游戏本体、客户端 jar、官方资源与库；不内置来源不明的整合包；不冒用官方品牌（命名、图标、文案不得暗示官方出品） |
| **离线账户** | 可作为合法身份来源实现，但必须明确告知用户"无法进入正版验证服务器"，且该告知在启动前不可被默认跳过；**其 UUID 仅作本地身份标识，不得冒充官方 UUID、不得伪造官方会话** |
| **第三方验证** | 可作为可选身份来源实现，默认关闭，由用户显式启用，并说明其依赖第三方服务的条款与可用性风险；不用于伪造官方会话，不接触官方验证接口 |
| **第三方服务条款** | 使用任何第三方内容源或验证服务前，须核对其条款；条款不允许的场景不实现 |
| **秘密处理** | 令牌一律以系统凭据保护加密存储；秘密值不进入可复现骨架、不写入日志、不进导出产物 |
| **解压安全** | 解压一律执行 zip slip 与路径穿越防护；越界条目整包拒绝且不落盘 |
| **证书与代理** | 证书异常必须明确分类提示；**不得静默忽略证书错误或以任何方式降级绕过** |

### 6.2 风险登记表

| 风险 | 类型 | 影响 | 缓解措施 |
|---|---|---|---|
| **离线账户进正版服务器被拒** | 功能/预期管理 | 用户认为"启动器坏了" | 每次启动**强制告知**身份来源能力限制；错误信息区分"服务器要求正版验证"与"网络/版本不匹配"；不假设启动器知道目标服务器 |
| **第三方验证服务断供** | 可用性/合规 | 该来源整体不可用 | 默认关闭；启用时展示依赖说明；与微软/离线来源完全解耦，断供不影响主链路；错误分类明确为"第三方服务不可用" |
| **authlib-injector 类兼容问题** | 技术 | 第三方来源无法启动或与其他加载器冲突 | 第三方来源自行声明所需额外 JVM 参数；参数注入集中在启动计划组装环节；与加载器参数合并顺序明确；版本升级导致不兼容时降级为"该来源暂不可用"而非崩溃 |
| **JRE 再分发许可** | 版权/合规 | 法律风险 | 仅选择许可允许再分发的构建；随附许可文本；运行时下载而非打包；建立运行时来源许可台账 |
| **镜像投毒** | 安全 | 注入恶意文件 | 校验基准恒定取自官方元数据；镜像仅作字节传输通道；校验失败即丢弃并回退官方源 |
| **镜像条款与断供** | 合规/可用性 | 功能下线 | 默认关闭、用户显式启用、来源可配置、UI 可见当前来源；一键回退官方源 |
| **启动计划泄露秘密** | 安全 | 令牌或身份信息外泄 | **骨架/秘密两平面分离；秘密以引用形式存在、启动瞬间才解析；导出与日志一律脱敏；一致性比对只针对骨架** |
| **解压路径穿越（zip slip）** | 安全 | 任意路径写入、系统被污染 | 解压安全规范：拒绝绝对路径与 `..` 越界、拒绝符号链接逃逸、限定受控根目录；越界条目整包拒绝且不落盘 |
| **代理与证书异常** | 安全/可用性 | 连接失败或被降级欺骗 | 明确支持代理配置；证书异常分类提示；**绝不静默忽略或降级绕过** |
| **微软 OAuth 前置条件不满足** | 合规/进度 | 微软登录不可上线，或违反条款 | P5 前置条件门禁：应用注册、client_id 与权限范围、回调/设备码、第三方启动器条款；**未满足不得进入开发完成态** |
| **更新机制被误判或更新失败不可回退** | 分发/可用性 | 杀软误报、更新后无法使用 | P7.0 在杀软误报、回退能力、单文件形态、冷启动影响四维完成选型；**更新失败必须可回退且用户数据无损** |
| 使用条款变化 | 合规 | 功能被迫下线 | 只依赖公开元数据接口；不把任何单一来源写死；保留可切换来源能力 |
| 令牌泄露 | 安全 | 账户被盗 | 系统级凭据保护（DPAPI）加密存储；不写日志；不落明文文件；登出即清除 |
| 日志泄露隐私 | 安全/合规 | 个人信息外泄 | 日志默认本地；**脱敏清单覆盖令牌、UUID、用户名、路径、IP、服务器地址**；导出前脱敏 |
| 捆绑第三方内容 | 版权 | 侵权 | 图标、字体、音效全部自制或使用明确许可的素材；建立素材来源台账 |
| 元数据格式漂移 | 技术 | 新版本无法启动 | 解析器前向兼容；未知字段忽略；契约测试覆盖多年代版本；P0 尖刺 S3 先行验证 |
| 路径与编码问题 | 技术 | 特定用户必然失败 | 中文/空格/超长路径专项测试（P0 尖刺 S7 先行验证）；统一以原生路径处理 |
| 杀软误报 | 分发 | 无法安装 | 避免可疑的自我替换与自解压行为；代码签名评估；P0 尖刺 S8 初判 + P7.0 选型 |
| 单文件自解压拖慢首启 | 性能 | 用户体验差 | 优先资源合并型方案；首启预算纳入 P7 验收；P0 尖刺 S1/S2 先行验证 |
| 磁盘与网络不可用 | 可用性 | 启动失败 | 预检 + 明确提示 + 断点续传 |
| 过度设计 | 工程 | 交付延期 | MVP 只做 Java 原版；抽象只在出现第二个实现时引入 |

## 7. 技术栈推荐（不展开实现）

| 层面 | 推荐 | 理由 | 明确不推荐 |
|---|---|---|---|
| 平台/形态 | Windows 桌面，单文件绿色版，双击即用 | 与目标形态一致；分发成本最低 | Web 套壳、需要用户预装运行时的方案 |
| 语言/框架 | C# + WPF（本工程已定方向，框架版本沿用既有约定） | 原生、体积极小、冷启动快、系统集成好 | Electron/Tauri 类重壳；JVM 系桌面框架；Qt |
| 目标框架 | 沿用既有 net48 路线（除非确认需要新 API，否则不换） | 目标机自带、产物 1–3 MB、冷启动最优 | self-contained 新框架单文件（体积膨胀一个数量级） |
| 架构模式 | MVVM + 分层 + 端口适配器 | UI 与引擎解耦，可测试 | 逻辑写进窗口事件 |
| 单文件化 | 依赖合并方案（资源合并型优先） | 不落地临时目录，首启不额外耗时 | 运行时自解压方案 |
| 网络 | 平台自带 HTTP 栈 + 连接池 | 零额外依赖，够用；代理与证书异常可控 | 引入重型 HTTP 框架 |
| 序列化 | 平台自带 JSON 能力 + 手写映射 | 元数据结构稳定，手写映射最稳、无反射开销 | 反射式大而全 ORM/框架 |
| 压缩 | 平台自带压缩库 | 满足 jar/zip 解压，配合解压安全规范 | 引入压缩库依赖 |
| 存储 | 本地文件 + 系统凭据保护（令牌） | 无数据库依赖，便携 | 嵌入式数据库（MVP 不需要） |
| 日志 | 自研轻量结构化日志（本地文件 + 脱敏） | 控制体积与格式，便于诊断导出 | 重型日志框架 |
| 测试 | 领域层纯单元测试 + 元数据"黄金样本"回归 + 启动计划骨架一致性回归 + 手动端到端清单 | 成本最低、覆盖最关键的解析与复现逻辑 | 早期追求自动化 UI 测试 |
| 更新机制 | 由 P7.0 四维选型决定（自替换 / 引导器 / 外部更新器） | 选型需兼顾杀软误报、回退、单文件形态与冷启动 | 未选型即动手实现 |
| 依赖策略 | **每引入一个第三方包都必须写明理由与体积代价，并参考 P0 尖刺结论** | 依赖越少，合并越简单、启动越快、风险越小 | 默认"先装了再说" |

## 8. 全局验收标准（Definition of Done）

| 类别 | 验收标准 |
|---|---|
| 功能 | **微软正版登录的前置条件（应用注册、client_id 与权限范围、回调 URI 或设备码、第三方启动器条款）已全部确认并有书面记录，否则不得标记完成**；微软正版账户可登录并启动官方正式版进入游戏主菜单；**离线账户可启动并在显著位置被强制告知无法进入正版验证服务器**；重复启动不重复下载；损坏缓存可自愈 |
| 可靠性 | 断网、坏文件、无 Java、磁盘不足、令牌过期、用户取消六类异常均有明确处理路径与提示 |
| 可诊断 | 任何失败都能导出诊断包，包含错误码、时间线、**启动计划骨架**、日志尾部；**导出经脱敏，不含令牌、UUID、用户名、路径、IP、服务器地址的真实值** |
| 可维护 | 领域层无外部依赖且可纯单元测试；新增一个后端不改动领域层 |
| 安全 | **令牌以系统凭据保护（DPAPI）加密存储、明文不落盘不进日志**；**启动计划秘密与可复现骨架分离，逐字节一致只比较骨架，导出脱敏**；**解压执行路径穿越防护，越界条目整包拒绝且不落盘**；**证书异常明确分类提示，绝不静默绕过**；离线身份不产生任何伪造官方会话的行为，其 UUID 仅作本地标识 |
| 合规 | 不打包任何官方游戏资源；不实现任何绕过验证的能力；素材来源有台账；JRE 来源有许可台账（仅在 P10 启用自动下载后适用）；启用镜像源时，校验基准必须可追溯到官方元数据 |
| 身份来源告知 | **每种身份来源的能力与限制在 UI 中可查；身份来源能力限制的告知在每次启动前强制出现且不可跳过；服务器兼容性预检仅在用户已提供目标服务器时执行，未提供时不得产生任何推断性结论；第三方来源启用时展示其条款与依赖说明** |
| 性能 | 单文件主程序体积与冷启动时间在 P7 设定的软预算内并通过实测；软预算已参考 P0 尖刺结论校准 |
| 兼容 | 中文路径、含空格路径、多 Java 共存、arm64 环境各有一份通过记录；相关结论与 P0 尖刺 S5/S7 一致 |
| 版本覆盖 | 至少覆盖 1.7.10 / 1.12.2 / 1.16.5 / 最新正式版 四个代表性版本 |

## 9. 已确认决策记录

> 本节为已确认决策，非待确认清单。背景与影响说明保留，便于后续评审时理解取舍理由。v1.1 的决策 1–5 保留并就地更新；v1.2 新增决策 6–11。

### 决策 1 · 身份来源

| 项 | 内容 |
|---|---|
| 决策 | 离线账户可实现，但必须明确告知用户"无法进入正版验证服务器"；第三方验证可作为可选实现，默认关闭，由用户显式启用并说明依赖第三方服务条款；绕过正版验证永不实现 |
| 红线改写 | 不伪造 Mojang 官方会话、不劫持官方验证接口、不实现破解登录；离线/第三方验证作为可选身份来源存在 |
| 背景 | 身份来源直接决定合规边界与 UI 文案；离线来源不依赖网络、实现成本低，且能让启动链路在认证接入前被完整验证 |
| 影响 | `IAuthProvider` 扩展为支持微软正版、离线账户、第三方验证三种实现，需能表达身份来源类型、是否在线验证、启动时注入什么、是否需要额外 JVM 参数；离线 UUID 仅作本地标识；**身份来源能力限制须在每次启动前强制告知** |
| 落地阶段（v1.2 更新） | **离线账户 → P4.0（P4 前置子任务）**；**微软正版 → P5（含前置条件门禁）**；第三方验证 → P10（默认关闭） |

### 决策 2 · 自动下载 Java

| 项 | 内容 |
|---|---|
| 决策 | 可设置；`IRuntimeProvider` 支持多实现（本机探测、手动指定、未来自动下载）；MVP 只做本机探测 + 手动指定；P10 增加自动下载，默认关闭，用户可开；只选许可允许再分发的 JRE 构建，附许可文本，运行时下载，不打包进主程序 |
| 背景 | 自动下载是提升"开箱可玩"的关键，但引入分发许可与体积风险；把许可约束写进契约，避免后续实现走偏 |
| 影响 | P3 验收标准明确"MVP 内不含自动下载行为但扩展点就位"；P10 增加许可台账与卸载能力要求；主程序体积预算不受运行时影响 |
| 落地阶段 | 探测 + 手动指定 → P3；自动下载 → P10（默认关闭） |

### 决策 3 · 镜像源

| 项 | 内容 |
|---|---|
| 决策 | 可设置；`IContentSource` 支持多实现（官方源、镜像源）；MVP 只官方源；P10 镜像作为可选，默认关闭，用户显式启用，来源可配置，用户知情 |
| 背景 | 镜像能显著改善部分地区下载体验，但带来投毒、条款与断供风险；必须从架构上隔离"传输通道"与"信任基准" |
| 影响 | P2 引入来源策略抽象并固化硬约束：校验基准恒定取自官方元数据，镜像不被采信为真源；P10 要求 UI 可见当前来源并支持一键回退 |
| 落地阶段 | 官方源 → P2；镜像 → P10（默认关闭） |

### 决策 4 · 体积与冷启动预算

| 项 | 内容 |
|---|---|
| 决策 | 按 C# + WPF + net48 的软预算执行：主程序体积 ≤ 5 MB（目标 1–3 MB）；冷启动到可交互 ≤ 800 ms（宽松上限 1.5 s）；空闲内存 ≤ 80 MB；首启不落地临时目录，首启与二次启动差异 ≤ 200 ms；作为软预算，P7 用实测数据再调，P0–P6 不为此牺牲架构 |
| 背景 | 目标形态是 PCL2 式的轻量单文件启动器，性能是产品力的一部分；但过早为体积优化会破坏分层与可维护性 |
| 影响（v1.2 更新） | P7 增加软预算表与测量条件、偏差归因要求；**软预算数值与依赖选择须结合 P0 技术验证尖刺（S1–S8）的结论校准**；明确"架构正确性优先于预算"的冲突处理规则 |
| 落地阶段 | P0 尖刺先行验证；P7 实测校准；P0–P6 仅做约束记录 |

### 决策 5 · 第二阶段优先级

| 项 | 内容 |
|---|---|
| 决策 | 先打磨 MVP（P0–P7）；第二阶段优先 Java 深度功能：多实例 → Fabric/Forge 加载器；之后做基岩版可行性预研，只调研不写代码；预研结论决定是否真正接基岩版 |
| 背景 | Windows 基岩版是 UWP/MSIX 体系，启动器可操控空间小，与 Java 版复用度低；在没有充分论证前投入实现风险高 |
| 影响 | P8+ 拆分为 P8 多实例 → P9 加载器 → P10 可选能力 → P11 基岩版可行性预研（零代码）；第 5 节增补"分发与沙箱体系"维度作为预研理由的书面依据；P11 默认预期为"不接或仅做极有限封装"，需报告证实或推翻 |
| 落地阶段 | P8 → P9 → P10 → P11 |

### 决策 6 · P4 与 P5 的阶段顺序（方案 A）

| 项 | 内容 |
|---|---|
| 决策 | 采用**方案 A**：把"离线身份最小实现"提前为 **P4 的前置子任务 P4.0**；P4 主体在离线身份就位后独立验收；**P5 专注微软正版与完整身份能力，不再承担离线身份职责，也不再阻塞 P4** |

| 落地阶段 | P4.0（P4 前置）→ P4 主体 → P5 |

### 决策 7 · LaunchPlan 安全与复现模型

| 项 | 内容 |
|---|---|
| 决策 | 启动计划拆为两平面：**A 可复现骨架**（版本 ID、Java 主版本要求、类路径顺序、natives 目录逻辑标识、JVM 参数模板、游戏参数模板、工作目录逻辑标识、环境变量键、身份来源类型、注入项键）与 **B 运行时秘密引用**（令牌句柄、令牌存储引用、敏感身份字段、解析后的实际绝对路径、时间戳等瞬时值）；**"逐字节一致"只比较骨架**；秘密仅在启动瞬间解析；**导出为人类可读文本时必须脱敏** |
| 背景 | 原"整份计划逐字节一致"不可实现：计划包含访问令牌、UUID、用户名、实际路径、Java 路径、时间戳等易变或敏感字段 |
| 影响 | P4 交付物与验收改写；P5 令牌存储与脱敏清单；`IAuthProvider` 契约以"注入项键 + 值引用"表达注入内容；第 3 节核心产物说明改写；第 8 节可诊断与安全验收增加"只比骨架、导出脱敏"；6.2 新增"启动计划泄露秘密"风险 |

### 决策 8 · P6 目标服务器预检边界

| 项 | 内容 |
|---|---|
| 决策 | 启动前**始终强制告知当前身份来源的能力限制**（尤其离线账户无法进入正版验证服务器）；服务器兼容性预检**仅在用户配置了服务器快捷连接、最近服务器记录或明确目标地址时才条件执行**；**不得假设启动器总能知道目标服务器**；无目标时不得给出任何推断性结论 |
| 背景 | 启动器通常不知道用户要连哪个服务器，原"当前账户 + 目标服务器是否可能被拒绝"的预检无法普遍落地 |
| 影响 | P6 任务/交付物/验收改写为"始终执行 + 条件执行"两类；第 3 节①与⑥同步；6.2 风险表缓解措施改写；第 8 节身份来源告知验收改写 |
| 落地阶段 | P6 |

### 决策 9 · P0 技术可行性尖刺

| 项 | 内容 |
|---|---|
| 决策 | P0 增加"技术验证尖刺（Spike）"子项：**不写产品代码，只验证关键假设，产出风险结论与处置建议**。验证范围至少包括：单文件资源合并首启是否落地临时目录（S1）、冷启动是否接近预算（S2）、手写 JSON 映射是否足够稳定（S3）、微软 OAuth 回调/设备码可行性（S4）、Java 探测与版本解析（S5）、DPAPI 凭据保护（S6）、中文/空格/超长路径（S7）、杀软误报初判（S8） |
| 背景 | 原 v1.1 把上述风险留到 P7 才实测，过晚；这些问题一旦在架构定稿后暴露，返工成本极高 |
| 影响 | P0 增加交付物"技术验证尖刺报告"与相应验收；**尖刺结论影响 P7 软预算与依赖选择**；涉及 OAuth 的结论汇入 P5 前置条件门禁；涉及路径与凭据的结论汇入 P2/P4/P5 安全基线；6.2 新增对应风险条目 |
| 边界与纪律 | **尖刺不产生产品代码；P0–P6 不因体积或冷启动预算牺牲分层、可测试性与扩展性** |
| 落地阶段 | P0 |

### 决策 10 · 更新策略选型提前

| 项 | 内容 |
|---|---|
| 决策 | 在 P7 前增加 **P7.0 更新策略选型决策点**，评估自替换、引导器、外部更新器三种方案，至少在**杀软误报、回退能力、单文件形态、冷启动影响**四个维度完成对比并给出结论；P7 再实现最终方案，**选型不得晚于 P7 开始** |
| 背景 | 原 v1.1 在 P7 才处理自动更新，但自替换更新与杀软误报、回退机制关系很大，选型过晚会连带影响发布形态与体积预算 |
| 影响 | P7 增加 P7.0 前置决策点与四维对比表；P7 交付物增加选型说明与回退验证记录；**更新失败必须可回退到旧版本且用户数据无损**；6.2 新增"更新机制被误判或更新失败不可回退"风险；第 7 节技术栈增加"更新机制"一行 |
| 落地阶段 | P7.0（P7 前置）→ P7 主体 |

### 决策 11 · 微软 OAuth 前置条件门禁与安全基线

| 项 | 内容 |
|---|---|
| 决策 | P5 必须完成前置条件确认：微软 OAuth 的应用注册、client_id 与所需权限范围、回调 URI 或设备码流程、第三方启动器相关条款限制；**任一未满足，微软正版登录不得进入开发完成态**。同时固化 MVP 安全基线：解压路径穿越防护、代理设置与证书异常分类处理、令牌以系统凭据保护（DPAPI）加密存储、日志与诊断导出脱敏（令牌、UUID、用户名、路径、IP、服务器地址）、离线 UUID 仅作本地标识 |
| 背景 | OAuth 前置条件属于外部依赖，若不确定即开发，会在收尾阶段变成不可上线的返工；安全基线若不前置，会在发布阶段暴露为高危缺陷 |
| 影响 | P5 增加前置条件清单与门禁验收；P2 增加解压安全规范与网络环境处理；P4 增加解压安全与日志脱敏；P4.0 增加离线 UUID 规范；第 3 节⑤⑥⑦同步；6.2 新增解压路径穿越、代理与证书异常、微软 OAuth 前置条件不满足三项风险；第 8 节功能、安全、可诊断验收同步 |
| 落地阶段 | P2 / P4 / P4.0 / P5 / P6 |
