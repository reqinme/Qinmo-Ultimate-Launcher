# Qinmo Ultimate Launcher · 秦墨

**多游戏启动平台**。Minecraft（Java 版 + 基岩版）是第一个产品，架构按"还能长出别的"设计。

> 状态：**M0 · 尖刺与地基（进行中）**。方案已定稿 **v3.13**，代码骨架刚落地（U0）。
> 上一轮以 C# / WPF / net48 实现的项目已整体封存于 `_archive/`，**只带走结论，不带走任何约束**。

| 项 | 值 |
|---|---|
| 技术栈 | Tauri 2（Rust 内核 + React/TS 界面），**前端零业务逻辑** |
| 架构支点 | 能力描述符（产品级 + 实例级，`reason` 必填）；**内核零 MC 词汇**（架构测试强制） |
| 界面 | 窗口取 DWM 系统材质（Mica→Acrylic→纯色），界面层零 CSS 模糊；三层材质 + 灵动岛 |
| 产品 | Java 版（全加载器）、基岩版（GDK / UWP 双形态）、未来其它 |
| 许可 | GPL-3.0（沿用封存项目的选择；引入不兼容依赖时需重新评估） |

## 两条决定性的技术事实

1. **Windows WebView2 上"窗口透明"与 CSS `backdrop-filter` 不能共存**（平台缺陷，非配置问题）。
   → 窗口取 DWM 系统材质，界面层放弃模糊，改由**不透明度阶梯 + 描边 + 留白**做层次。
   → 意外收益：成本更低、旧系统不塌、设计语言收敛。

2. **基岩版自 1.21.120 起由 UWP 迁移到 GDK**，数据目录搬到 `%appdata%\Minecraft Bedrock\...`（普通文件系统）。
   → 行为包 / 资源包 / 皮肤包 / 世界都可正常管理，基岩版从"只调研"升为**正式支持**。
   → 但多实例隔离受限，能力描述符如实声明 `isolation:false`，界面自动少渲染入口。

> **⚠️ 上述第 1 条是本项目最大的未验证假设**：自绘标题栏要求无边框窗口，而**无边框正是 DWM 材质
> 历史上不生效的高发场景**。它由 M0 的 **S1 尖刺**（4×2 矩阵实测）判定，**A / B1 / B2 三档预案已写死在
> `docs/UI设计规格.md` §11.2**——S1 出结论后直接对号入座，不需要临场决策。

## 开发

```bash
pnpm install            # 前端依赖
pnpm typecheck          # 类型检查
pnpm lint               # 含三条纪律规则（禁字面颜色值 / 禁按产品名分支 / 禁 toggle 布尔状态）
pnpm test               # 前端测试（契约校验 + 渲染）

cargo test --workspace  # Rust 测试（含架构约束：内核零 MC 词汇、能力必须登记进 ALL）
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all --check
```

**环境要求**：Rust stable（MSVC 工具链）· Node ≥ 22 · pnpm 10 · **JDK 8 / 17 / 21 三套**（M0 需实测三个 Java 版本）·
WebView2 运行时（Win11 自带）。Windows 仅此一端（Tauri 2 的 Windows 目标是唯一目标平台）。
