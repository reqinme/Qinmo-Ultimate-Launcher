# 加 Tauri 会引入什么：**实测**

> **这份文件的每一条都是在本机量出来的**，不是从文档抄的。
> 取证工程：`spikes/m1-tauri-tree/`（**在 workspace 之外**，见其 `Cargo.toml` 的 `[workspace]`），
> 完整 crate 清单：`spikes/m1-tauri-tree/tree-names.txt`。

---

## 0. 为什么这件事需要"量"而不是"判断"

产品的 `Cargo.lock` 现在**只有 18 个包**（serde 全家 + thiserror），
而 `crates/qul-infra/src/winhttp.rs` 连 https 都做到了**零新依赖**
（用 Windows 自带的 WinHTTP）。

**所以"加 Tauri"改变的不是"代码写不写得出来"，而是"我们欠多少维护与许可证台账"。**
而那件事只能量。

---

## 1. 一句话结论

| | |
|---|---|
| **新增 crate** | **约 210 个**（18 → **218**） |
| **首次构建**（debug，本机） | **36.7 秒** |
| **target 体积** | **1521 MB** |
| **许可证** | **全部宽松**（详见第 3 节） |
| **是否需要 C 工具链** | **不需要**（`cc` 不在树里 —— 这一点与 `ring` 不同） |

**而它不需要拍板** —— 方案 §3.5 与 §4.5 已经把 Tauri 2 定成栈，
而替代品（WinUI / 原生 Win32 FFI）等于重写整个技术方案。
**所以上面这些数是台账，不是选项。**

---

## 2. 依赖树里都是什么

按前缀归类（218 个里）：

| 类 | 个数 | 它们是什么 |
|---|---|---|
| `other` | 125 | 大多是 `futures-*` / `pin-project` / `aho-corasick` / `anyhow` 这类底层件 |
| **serde 家族** | 18 | 我们**已经**在用（`serde` / `syn` / `quote` / `proc-macro2` 等） |
| utility | 16 | `libc` / `once_cell` / `bitflags` / `smallvec` / `indexmap` |
| **`windows-*`** | 16 | Windows API 绑定（WebView2 / COM / 窗口） |
| config-fs | 12 | `toml` / `glob` / `notify` / `regex` / `walkdir` |
| **http-stack** | 10 | `http` / `url` / `idna` / `bytes` / `percent-encoding` |
| **`tauri-*`** | 9 | `tauri` / `tauri-utils` / `tauri-build` / `tauri-macros` / `tauri-codegen` / `tauri-runtime` / `tauri-runtime-wry` / `tauri-winres` |
| **gui-stack** | 7 | `wry` / `tao` / `muda` / `webview2-com` / `raw-window-handle` |
| crypto | 5 | 哈希与随机（`digest` / `uuid` / `getrandom`） |

### 而 `window-vibrancy` 是**我们确实要的**

方案 §3.4 的材质降级链（Mica → Acrylic → Tabbed → 纯色）要靠它。
**它是"顺手加的"的反面** —— 没有它，"窗口取 DWM 材质"就没有落点。

## 3. 许可证：**全部宽松**

从**本地已解开的 crate** 读 `license` 字段（不是从文档抄）：

| 许可证 | 个数 |
|---|---|
| `MIT OR Apache-2.0` | 105 |
| `MIT` | 40 |
| `Apache-2.0 OR MIT` | 23 |
| `Unicode-3.0` | 18 |
| **`MPL-2.0`** | **5** |
| 其余（`BSD-3` / `Zlib` / `CC0` / `0BSD` / `Unlicense` 及其组合） | 22 |

### ⚠️ 那 5 个 MPL-2.0 值得单独说

它们**全是 CSS 解析**：

```
cssparser / cssparser-macros / selectors / dtoa-short / option-ext
  ← dom_query  ← tauri-utils  ← tauri-build  ← tauri
```

- **MPL-2.0 是文件级 copyleft** —— 它要求"改了那些文件就要公开那些文件"，
  而**不传染**链接它的代码。我们**不改它们**，所以它只要求**保留许可证文本**。
- **而它们的来源是 `dom_query`** —— 一个 HTML 查询库，而它进树的路径是
  **`tauri-build`（构建期）**，用于在构建时处理 `index.html`。
- **台账落点**：它们要进 `docs/来源记录.md`，并标注"MPL-2.0，未修改，仅构建期使用"。

### 而 `Unicode-3.0` 那 18 个是 ICU4X

`icu_*` / `zerovec` / `yoke` / `tinystr` … —— 它们随 **`url` / `idna`** 进来
（URL 解析要做 IDNA 规范化）。而 `Unicode-3.0` 是 **Unicode 联盟的许可**，
**宽松**（MIT 类，要求保留版权与许可声明）。

## 4. 构建时间与体积：**实测**

| 项 | 值 |
|---|---|
| 首次 `cargo build`（debug，**本机，全部依赖从零编译**） | **36.74 秒** |
| 产物 `tauri-tree-probe.exe`（debug） | **0.1 MB** |
| `target/` 总大小 | **1521 MB**（2698 个文件） |

**⚠️ 而这三条都要说清它们的边界：**

1. **36.7 秒是 debug 且本机（Ryzen 级桌面 CPU、NVMe）**。
   **release + LTO 会慢得多** —— 而产品的 `[profile.release]` 是
   `opt-level = "s"` + `lto = true` + `codegen-units = 1`
   （**体积优先**，见 `Cargo.toml`）。所以那个数字**不是**发布构建的时间。
2. **0.1 MB 的 exe 不是真实体积** —— 它是一个空 `main()`，
   而 WebView2 **由系统提供**（方案 §7 的预算里那 400 MB 就是它）。
3. **1521 MB 的 target 是"全量依赖的编译产物"**，
   而它**不进安装包**（方案 §7 的验收条件是安装包大小，不是 target 大小）。

## 5. 而它对**产品**的依赖面影响：可控

`src-tauri` 由 `Cargo.toml` 的 `exclude = [...]` 挡在 workspace 之外 ——
**于是它有自己的 `Cargo.lock`，而产品的那个仍然是 18 个包。**

这不是"绕过"：它买到了两件真实的东西：

| # | 好处 |
|---|---|
| 1 | **产品的依赖面是一份可审计的短清单** —— `cargo tree -p qul-core` 仍然是 3 个包 |
| 2 | **内核与基础设施的测试不需要先编 210 个 crate** —— `cargo test -p qul-core` 仍是秒级 |

而代价是：**`src-tauri` 的依赖要单独看**（一条 `cargo tree --manifest-path src-tauri/Cargo.toml`）。
**那条命令会写进 `docs/来源记录.md`。**

## 6. 而它**不需要**你决定

| 方案 | 判断 |
|---|---|
| **Tauri 2** | ✅ 方案 §3.5 / §4.5 已经定了它 |
| WinUI 3 / 原生 Win32 FFI | ❌ 等于重写整个技术方案（§4.5 整节） |
| Electron | ❌ 违反 §3.5（体积与内存预算） |
| 不做 GUI | ❌ 那这个产品不存在 |

**所以上面这些数是台账，而不是选项。** 我按方案继续。
